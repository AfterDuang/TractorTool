## 怎么阅读

- 首次了解项目：先读根 README；具体实现和验收状态继续查看开发与验收。
- 接续开发：按根 AGENTS.md 阅读产品需求、架构、开发与验收、开发上下文，再核对源码。
- **默认不读项目历史**。只有追查某次变更、选型依据、命令或回归时，才通过 E 编号/主题索引读取相关片段；归档 M1 不表示将历史缺证项改为通过。
- 开发或修改插件：加读插件开发规范和 `Plugins/<插件名>.md`。首版两个插件使用相同公开 SDK；独立测试插件只是机制夹具。
- 了解“做到了什么、是否通过”：只以开发与验收中的当前状态及对应证据为准。插件文档中的设计、示例和验收方法不代表已有实现。

## 怎么维护

1. 宿主需求变更写产品需求；公共结构和服务边界变更写架构；跨插件接入规则变更写插件规范；具体业务变更只写对应插件文档。
2. 保留 R01–R17、A01–A23 和 E 编号。当前验收状态只写 DEVELOPMENT.md，历史执行详情只写 PROJECT_HISTORY.md；产品中的插件条目仍是范围索引。
3. 实质性进展替换 DEVELOPMENT.md 的当前摘要、更新验收状态，再刷新 PROJECT_CONTEXT.md。交接只保留当前边界、关键入口和下一步，不复制整个架构或验收表；插件详细验收方法链接到对应文档。已完成的轮次归历史并链接，旧产物路径不继续充当当前运行入口；未关闭问题、仍有效约束及当前操作入口不得只留在归档。
4. 新增正式插件时，在 Docs/Plugins 下建立一份文档，包含范围、需求、宿主依赖、内部设计、错误边界与验收方法，并从本页链接。不另建插件专属的 Agent 指令入口。
5. 用户新指示优先于旧文档；整理结构不能删减已确认语义，不能将待验证方案改写成已实现。
