# AB 审片插件

需求与设计；当前实现、产物和验证结果统一见[开发台账](../DEVELOPMENT.md#media-compare)。

## 范围与交互

- 左 A、右 B，各自打开本地视频、单图或编号图片序列。拖入带末尾编号的图片时，按同目录、同前缀、同扩展名及一致补零规则发现后续帧；至少两帧才自动识别为序列，允许 `9→10` 等自然进位，缺号报错。普通“打开”始终打开单个文件，“⋯ → 选择序列首帧”显式打开序列；序列帧率由用户指定。
- 共同时间轴控制播放、暂停和定位；A/B 可采用不同编码、尺寸与帧率。每一路按自己的实际帧时间更新，交换左右不改变配对或刷新节奏；不把两个文件相同帧号当作同一时间。自然播完后再次播放从开头开始，普通暂停仍从当前位置继续。精确前后逐帧需要邻帧时间索引，当前不以名义 FPS 加减冒充逐帧。
- 两边共用归一化图像中心与缩放比例，保留各自显示宽高比，包括非方形像素。底部“适合画面”恢复完整画面并重置中心与缩放，双击也可恢复；移除“填满画布”和“1:1”，常用操作围绕对比画面与共同时间轴排列。
- 声音选择静音、只听 A、只听 B，切换完成前暂时禁用选择；无音轨、缺解码器或无法建立输出分别提示，不提交失败选择。替换当前试听侧为无音轨素材时恢复静音。时间轴上限取两边媒体估计时长的较短者；容器可能包含仅音频尾段，定位无视频帧时立即提示。单图持续保留，不限制另一边的视频时长。
- 拖动时暂停播放，以单个在途解码及单个最新待处理位置节流；拖动请求开始间隔至少 16 ms，解码耗时计入间隔，不在每次完成后再固定等待。首次、点击和松手定位不额外节流；松手取消旧请求并定位最终位置。滑块为请求时间，预览异步到达；不承诺移动中的滑块与正在提交的 GPU 帧同时更新。PR 式流畅度属于待实测目标，不能由库名、GPU 标志或构建成功推定。
- 长 GOP 素材的逐帧代理、邻域缓存、前后邻帧索引及素材时间偏移是后续性能/对齐工作，不能用低分辨率代理冒充原片细节。当前操作必须显示实际支持情况。
- 空格播放/暂停，长按只触发一次；输入文字、编辑帧率或操作声音下拉框时保留控件自身键盘行为。静态图片不显示时间轴和播放按钮，保留缩放、平移与适合画面。
- A/B 各自的标题与画布整个区域接受一个本地文件，拖入时突出目标侧，离开即取消提示。保留文件选择入口，参照 Apple HIG 的[拖放反馈与替代操作](https://developer.apple.com/design/human-interface-guidelines/drag-and-drop)。
- 画面占据主工作区，A/B 标识、素材名和简要尺寸紧邻各自画布。“⋯”包含素材信息、移除当前侧及显式序列打开；移除一侧暂停播放并保留另一侧。“清空对比”移除两侧并重置时间、试听选择、视图和序列帧率，回到初始界面，均不删除源文件。“说明”收纳手势、预览限制与运行库信息。布局借鉴 Apple HIG 的[工具栏分组](https://developer.apple.com/design/human-interface-guidelines/toolbars)和[播放交互](https://developer.apple.com/design/human-interface-guidelines/playing-video)，控件和主题仍遵循宿主。

## 依赖与宿主边界

采用官方 GStreamer 1.28.9 的公开 C ABI 与 D3D11 能力，不修改上游，不引入完整 GES 剪辑模型。运行库与 GPU 互操作库是插件私有依赖，随插件交付；包含 Blu-ray LPCM 所需的 `dvdlpcmdec`，不依赖系统 PATH、另装播放器、FFmpeg 命令行程序或 Python 环境。来源及许可见[运行库材料](../../Plugins/TractorTool.Plugins.MediaCompare/Native/Runtime/README.md)。

`dependencies` 为空表示未通过宿主 Packages 申请外部工具，并不表示没有运行库。现有 Packages 仅支持 GitHub Release ZIP 内可执行工具及版本输出校验；DLL-only 运行库的声明、完整性校验、来源及进程期占用保护尚无公开契约。若改为首次申请，须先交架构侧分析，不把 DLL 伪装成工具，也不另建运行时下载器。

只引用公开 Contracts/UI；媒体引擎、时间映射、GPU 资源与缓存均归插件。注册页使用现有 Avalonia 控件能力；若必须修改宿主、Core、Contracts 或公共 UI，停止该项实现并交由架构侧分析。包体仍遵循[现有安装限制](../PLUGIN_DEVELOPMENT.md#3-运行目录与打包)。

## 内部职责

| 部分 | 责任 |
| --- | --- |
| `ComparePlugin` | 轻量初始化、页面注册、插件停止 |
| `Media/ComparisonSession` | 共同时间、播放状态、定位作废、帧配对及资源释放 |
| `Native/Interop` | 固定版本 C ABI、私有 DLL 初始化，不向宿主泄漏原生接口 |
| `Rendering`、`Views/ComparePreview`、`Views/PreviewLifetime` | GPU 合成、共享纹理同步、联动视图及预览退场等待 |
| `CompareViewModel`、`CompareView` | 用户操作、素材选择、时间轴、状态与页面订阅 |

原生样本有界持有：会话每侧保存当前帧与下一帧，验证缺失时长的候选时最多再预读一个后继；原生 appsink 队列及渲染在途帧另有各自上限。暂停保留当前解码样本以便切页返回，不能声称解码表面已全部释放。画面复制到插件纹理后，以样本身份跳过未变化一侧的重复上传；身份与 PTS、可复用纹理地址分开，清空或重建即失效。UI 更新合并，不能将每一帧无限排入 Dispatcher。

解码时间戳、帧区间与内部播放位置保留纳秒，仅在 UI 边界转换为 `TimeSpan`。播放取两路真实 PTS 的并集，以共同 `GstClock` 调度，不固定 A 为主路；低帧率一侧保持有效帧，另一侧继续更新。两路固定帧率的时间戳若仅因 floor/ceil 相差 1 ns，且可证明是同一有理数网格边界，才采用较晚的实际起点并严格验证两侧覆盖；不普遍放宽容差，不用相同帧号对齐不同帧率素材。

连续播放按相邻真实 PTS 选择画面：`当前 PTS ≤ t < 后继 PTS` 时保持当前图像，到后继实际时间才换帧。原生 duration 可能是独立取整的名义帧周期，不能仅凭 `PTS + duration < 后继 PTS` 判定素材损坏或缺帧；稀疏时间戳也按此规则呈现停帧，不宣称素材连续性已验证。不改写 PTS，不设置容器专属或任意毫秒容差。原生时长仍用于定位首帧及 EOS 边界；未知时长的最后一帧不能延长至容器音频尾段。`0/1` 表示可变帧率，不套用默认 FPS。自建图片序列按生成器的有理数帧率计算边界。配对完整后才提交两侧画面与位置，时间倒退、缺 PTS 和原生解码错误仍拒绝。

普通暂停和单侧移除保存共同播放时钟的实际时刻，并限制在当前呈现区间内；低帧率画面没有更新时，声音也不能因此回退到旧视频 PTS。自然结束后的重播仍从零开始。续播仍通过原生准确定位恢复：取整空窗可反馈稍后的实际可达时间；真正长空窗内定位或续播可能被拒绝并保留原画面，不能将连续播放的停帧策略外推为任意位置均可准确定位。

显示几何取最终协商的像素宽高比：显示宽度为像素宽度乘 PAR，渲染适配、光标缩放和平移共用该尺寸；纹理分配与复制仍使用实际像素尺寸。声音选择以会话成功提交的 `SelectedAudio` 为唯一来源，界面不再根据媒体描述另行推断。

定位以实际可达时间反馈：容器取整若返回稍后的首帧，仅在有固定帧率、有效帧区间且前移不足一帧时，允许按两侧实际起点的较大值重新定位一次。两侧须严格覆盖新的共同时间才能提交；再次不对应、超出范围或未知时间仍失败。不放宽覆盖容差，也不把实际前移伪装成原请求位置。

双路定位仍由同一个 worker 管理：先分别发出 `FLUSH | ACCURATE`，再收取两路 preroll 并等待各自包含音频的管线完成暂停，使原生解码准备能够重叠。只有两路均校验通过才提交画面；不把 GStreamer 的发出定位调用本身视为无阻塞异步调用。

完全准备好的共同位置以精确纳秒记录；重复同位置或定位后立即播放可复用这对 preroll，命中时仍检查原生错误并重新发布。开始播放、替换素材、清空、准备新位置、失败或取消会使该记录失效；普通播放后的暂停续播仍重新准确定位。它不缓存邻近位置，也不复用仅因 UI 时间截断看似相同的请求。

## 失败与生命周期

- 无运行库、缺解码器、损坏/不可读素材、超时、显卡不兼容均给出原因，不展示模拟帧。播放异常保留原异常与堆栈交给宿主日志，界面只显示错误摘要。
- 当前解码器与 Avalonia 必须使用同一 GPU；使用公开的 D3D11 共享纹理接口，不支持软件渲染后端或跨 GPU 纹理转移。预览失败会暂停声音与解码，恢复前禁用播放。
- 格式覆盖以实际分发模块和转换能力为准。允许已支持的 10/12/16 位 SDR 源转为 BGRA8，并在对应画布上方持续标注“源位深 → 8 位预览，不用于判断原始色阶精度”。这不构成高精度显示链；HDR、Log、广色域及 EXR/HDR/DPX 输入仍未支持。独立 HDR mastering/content-light 元数据也会触发拒绝，不能因 transfer/primaries 缺失而放行。
- 源端同步检查第一份格式；后续非等价格式或色彩标记变化会锁存错误并阻断数据，定位产生的重复等价格式允许通过。缺失/错误元数据不能证明素材不是 Log，也不等于已经做了显示器色彩校准。
- 替换素材失败应保留原先有效会话；定位取消不记录 Error，不提交过期画面。
- 缺少帧时长且没有固定帧率的素材，原生准确定位可能裁剪 PTS；非零位置不能仅凭裁剪后的时间戳证明对应帧。因此明确暂停并提示从开头播放，不静默显示未来帧；非零暂停后的续播也可能受限。完整 VFR 随机定位仍需邻帧索引，带有完整时间信息的 VFR 样本通过不代表该限制已解除。
- 切页解除显示订阅并暂停交互播放，保留已打开素材与位置；返回时重新发布持有的有效帧对，不从 UI 截断后的时间重新定位。当前没有代理转码后台任务。
- 音轨状态来自真实流信息、缺模块消息和输出端格式协商；“可用于试听”不等于扬声器音量或音画同步已验收。解码及输出设备的运行异常仍暂停播放并报告。
- 页面退场跟踪初始化、在途呈现和图形释放，快速重进等待前一代退场。插件停止关闭新预览注册，同时取消媒体操作并等待媒体与全部预览退场完成；退场完成后即使清理失败也解除 UI 对象登记，仅保留首个异常供停止时报告。不调用进程级 `gst_deinit`，不强杀宿主。

## 验收方法

1. 两条带帧号/时间码和同步音频标记的素材：共同播放、暂停、反复拖动、时间轴键盘定位、末尾及仅音频尾段；核对实际画面时间，不能只看滑块。视频/序列交换 A/B 后应保持配对；1 fps 与高帧率组合应各自刷新。分别检查普通暂停续播和自然结束重播。
2. 中文/空格/百分号路径、静态透明图片、拖入首帧自动识别、普通打开单图、自然进位与缺号序列、24/25/30 fps 以及可变帧率；检查定位到关键帧附近的实际落点及视频/序列混合配对，拒绝损坏文件后再次打开正常文件。
3. 不同宽高比和分辨率：包含 720×576、PAR 16:15 与 768×576 方形像素的等效素材；使用可识别上下左右的画面，检查方向、光标缩放锚点、顺向联动平移、适合画面、125%/150% DPI、缩放窗口。
4. 静音/A/B 声音切换、无音轨及缺解码器提示、AC3/LPCM M2TS；切页重返、隐藏到托盘、连续替换、播放中退出，检查原生资源与日志。
5. 双 4K 长 GOP 正倒拖，记录冷定位/缓存定位延迟、丢帧和显存占用；普通可播放不能代替性能验收。
6. 从独立 ZIP 安装到干净宿主，不依赖开发机运行库；检查私有 DLL、许可、压缩/展开体积及平台限制。
7. 焦点依次位于预览、时间轴、打开/视图/播放按钮时按空格；长按不反复切换，序列帧率输入和声音下拉框保持自身交互。反复播放→暂停→拖动→播放，末尾再播放；核对暂停超时及 segment 警告是否仍发生。
8. 从 Explorer 拖文件至 A/B 标题及画布，检查目标提示与替换失败后的原素材；拒绝目录、多文件和非本地项目。播放或定位期间移除一侧、清空全部并重新打开，核对画面、时间和试听状态，确认源文件不变。
9. SDR 10 位视频、16 位 PNG 单图/序列转换与持续精度提示；含 HDR 色彩标记或独立 HDR SEI 的素材应拒绝。缺失标记不构成色彩准确性证明。

自动验证入口为 [MediaCompareChecks](../../tests/TractorTool.MediaCompareChecks)。不带参数时仅检查样本所有权、视图数学、帧时间边界与序列文件校验，不初始化媒体引擎或窗口。

显式传入 `--gpu-playback <runtimeRoot> <newScratchDirectory> <syntheticA> <syntheticB>` 时运行独立 Windows GPU 诊断；四个路径必须绝对路径，临时目录必须不存在，素材使用自行生成的 SDR 8 位视频（至少 8 秒，建议 12 秒、720p H.264＋AAC，包含固定/可变帧率组合）。它复用 `ComparisonSession` 和 `ComparePreview`，创建不激活、不显示在任务栏的屏幕外窗口，检查多点定位、取消后保留最新请求、试听命令、单侧移除、全部清空后重开播放，以及快速重进、初始化/呈现在途停止和重复释放。另从预览子控件派发空拖放事件检查冒泡处理与拒绝，不等于 Explorer 原生文件拖放验收。不加载宿主、用户配置或已安装插件；用法见[插件源码入口](../../Plugins/TractorTool.Plugins.MediaCompare/README.md#独立播放诊断)。

诊断日志位于新临时目录的 `diagnostic.log`，记录操作阶段、UI 心跳、解码时间推进和帧交付计数。退出码 0 说明该组合的操作、媒体停止与预览异步退场已完成，且未发现心跳停顿或非预期错误；不证明所有驱动显存分配已回收。退场失败另用模拟异常检查弱引用可回收与首错保留，不是实际驱动故障注入。帧交付不等于画面已正确呈现，不覆盖声音质量、同步精度、可见 UI 或所有硬件。

`--media-inputs <runtimeRoot> <newScratchDirectory> <fixtureRoot>` 不创建窗口，使用合成素材检查纳秒定位边界、视频/序列双向实际像素配对、混合帧率刷新、暂停/结束重播、PAR、GPU 上传复用及缓存失效；独立的 `prepared-seek-reuse` 项检查重复定位发布、定位后续播复用和开始播放后的失效。并覆盖重返页面帧保持、PNG/JPG/16 位 PNG、持续降精度提示、HDR 拒绝、M2TS 音轨及非静音 PCM 解码。包含 MKV/M2TS/MP4 的拖动后播放、取整空窗、暂停续播及左右混合检查；仅运行该子集用 `--seek-play`，参数相同，不包含准备状态复用项。日志为 `inputs.log`；GPU 像素读回不等于显示器最终呈现，非零 PCM 不代表扬声器实际可闻或 A/B 音画同步。素材布局见[诊断入口](../../Plugins/TractorTool.Plugins.MediaCompare/README.md#独立输入诊断)。

原生阻塞不能靠托管 `WaitAsync` 超时强行中断。启动者必须另行监控诊断进程，停滞时先采集该进程的线程/转储，再终止该诊断进程；不能终止真实宿主或无限等待。运行授权仍遵循根 [AGENTS.md](../../AGENTS.md)，诊断不得擅用真实素材和应用数据。
