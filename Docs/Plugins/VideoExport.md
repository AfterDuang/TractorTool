# 视频多版本导出插件

## 1. 范围与依据

本文集中维护首版视频插件的业务需求、内部模型、媒体处理和验收方法，对应 [产品需求](../TractorTool.md) R08、R10–R17。公共接入规则见 [插件开发规范](../PLUGIN_DEVELOPMENT.md)，宿主包服务、进程服务与任务所有权见 [软件架构](../ARCHITECTURE.md)。

M3 验证真实媒体链路，M4 完成多预设交互与公共有限任务接入。本文定义业务行为及处理边界；已有代码不代表真实媒体验收通过，当前进度和 A09–A21 等验收结果只记录在 [开发与验收](../DEVELOPMENT.md#acceptance)。

## 2. 已确认行为

### 2.1 操作模型

导航与设置入口共用 Microsoft Fluent System Icons 的彩色 Video 图标，与系统数据 HUD 同系列；保留单色 Video 符号作为图片加载失败时的回退。原始素材见 [SVG](../../Artwork/fluent-video-32-color.svg)，来源及 MIT 许可说明见[插件声明](../../Plugins/TractorTool.Plugins.VideoExport/NOTICE.md)。页面内操作图标仍随主题显示。

一次输入一个源视频，可以再选择一张封面图片。用户创建和保存多张预设卡片，选中其中若干张，一次提交导出。

页面右上角通过页签切换“多格式导出 / 视频信息”。导出页左侧以“导出参数”为固定小标题，下方是紧凑的单视频/可选图片拖放区及参数编辑器；右侧“导出预设”与左侧标题对齐，两侧首张卡片从同一高度开始。添加预设后在右侧显示卡片，支持勾选、编辑、复制、删除及各自进度。空路径、空错误和未开始的进度不占卡片空间。窄窗口左右区域改为上下排列，各区域标题保留在滚动区外，内容独立滚动。页内切换复用公共 PageHost 动效。

输出操作栏固定在整个导出工作区底部，与滚动的输入/预设区域分开；复用主题卡片，以文件夹图标、“保存位置”标签和路径说明目的地。未选择时明确提示设置保存位置，并提供有背景的“选择文件夹…”按钮；选择后显示路径和“更改位置…”，长路径省略并可悬停查看完整内容。路径操作与主操作“导出选中版本”相邻，导出使用主题强调色，添加/保存预设用普通按钮；按钮高度一致。窄窗口将操作按钮排到路径下方，继续保持可达，不能被长预设列表挤出视口。忙碌时不可更换输出目录，取消文件夹选择保留原路径；沿用现有命令可用性和导出流程。

用户明确：视频信息页是类似 MediaInfo 的信息提取，不是播放器，也不需要首帧预览。左侧拖入一个本地视频或选择文件识别，右侧一个只读、可选中/复制的文本框，按容器、视频/音频/字幕轨、章节、节目等分组展示；完整保留 ffprobe 返回的嵌套元数据与未知字段，不只列摘要。不枚举逐帧/逐包内容，不声称字段集合与 MediaInfo 工具完全相同。

例如，一个 4K 源视频可以按 `1080P_200mb`、`4K_加封面` 等预设生成不同版本。名称只是用户定义的标签，程序只读取卡片实际参数，不从名称解析分辨率、文件大小或封面设置。

这里的批处理是“单视频、多预设、多版本”，不支持同时输入多个源视频，也不并行导出多个版本。

### 2.2 预设卡片

每张卡片独立保存：名称、输出格式、码率模式（VBR 一次 / VBR 两次 / CBR）、视频码率、音频码率，以及画面选项中的尺寸与首帧替换。编码器由插件按输出格式和 GPU 偏好选择，不再由每张卡片选择硬件品牌或编码器名称。

预设可新增、编辑、复制、删除和复用，并在软件重启后保留。源视频和封面属于本次导出输入，不作为预设固定绑定的文件；同一预设可以用于下一个视频。

左侧编辑器作为草稿，“添加预设”保存成卡片；点击卡片“编辑”将参数载入左侧，“保存修改”更新该卡片并清除旧结果状态。主要参数保持展开，尺寸/首帧替换收于“画面选项”；编辑带这些选项的旧预设时自动展开。预设名称、参数及勾选状态自动持久化，输入/输出路径不写入偏好。旧设置沿用 schema 1：缺少 RateControl 时默认 VBR 一次，忽略并在下次保存移除旧 Encoder 字段，保留 ID/名称/尺寸/码率/封面/勾选；缺少 GPU 偏好默认关闭。损坏配置保留并显示错误；运行中锁定输入与预设编辑，但功能页切换、卡片取消仍可用。

码率输入显示明确单位，分辨率显示实际宽高。`1080P`、`2K`、`4K` 等名称不代替宽高数据。选择多个预设后，每个预设产生一个独立输出文件。

### 2.3 封面替换

各预设可单独开启或关闭封面替换，但共用本次选择的同一张图片。开启替换却没有图片时，导出前提示补充图片或关闭该选项。

图片按该版本最终输出尺寸等比缩放、居中裁剪并铺满画面。只替换第一帧，不额外插入片头、增加封面停留时长或改变后续音画对应关系。不把附加图片流、文件管理器缩略图或播放器封面显示当成该功能的完成证据。

### 2.4 导出与任务

- 支持多种输出格式，验证容器、视频编码器、音频编码器之间的组合。
- 支持 CPU 和可用的 GPU 编码；可用能力取决于实际工具包、显卡和驱动。
- 按选中预设的顺序逐个导出，显示当前任务、其他版本状态、进度和错误。
- 支持取消单个任务或本批后续任务；切换页面和隐藏到托盘不终止导出。
- 输出文件不能覆盖源视频，也不能静默覆盖已有文件。
- 提交任务时固定参数，之后编辑预设不会改变已经入队的任务。

### 2.5 媒体信息与大小预估

读取源文件的时长、宽高、帧率、容器、视频编码、音频流和可获得的码率等信息。缺失或不适用的信息显示未知，不编造数值。

根据时长及用户设置的视频、音频码率预估每个版本的大小。界面标记为预计值，实际值可能因编码行为和容器开销不同而变化。不提供目标 MB 输入框，也不因预设名称包含 `200mb` 自动调整码率。

## 3. 与宿主的边界

| 宿主公共能力 | 视频插件自己的责任 |
| --- | --- |
| 外部包下载、校验、版本路径和使用租约 | 声明 FFmpeg/ffprobe 依赖，解释媒体能力与编码选择 |
| 受管理的进程执行、输出读取、取消 | ffprobe JSON 解析、FFmpeg 参数与滤镜编排、进度解释 |
| 有限任务的公共状态与取消入口 | 预设快照、视频串行策略、输出校验和结果模型 |
| 通用设置与插件数据目录 | 编码器偏好、预设格式与模型迁移 |
| 页面注册和公共主题 | 输入区、预设卡片、媒体信息、导出状态和专属设置页 |

包管理契约归 Contracts/Packages，实现归 Core/Packages，管理页归宿主；FFmpeg 文件归数据根目录 Packages。视频插件使用 API 1.4 的 TryRequestAsync 申请 FFmpeg 固定版本：已安装则复用，缺失由宿主确认并安装；“先不安装”返回空租约，保留视频选择、结束忙碌状态并允许重新读取，不产生取消异常。取得租约后持有至进程和输出读取结束。插件不自建下载器，不依赖 Core 内部实现。插件使用 API 1.6 Tasks 登记整批导出，并要求 API 1.7 显式记录日志级别，UI API 仍为 1.3，需要更新宿主；当前验收状态只见开发台账。

## 4. 内部设计

以下模型名与处理流程为设计约定，实际类型和实现须经对应阶段验证。

### 4.1 数据模型

| 模型 | 责任 |
| --- | --- |
| `MediaInfo` | 源文件探测结果、视频与音频流、旋转、时间基准和显示尺寸 |
| `ExportPreset` | 稳定 ID、名称、格式、实际宽高、视频/音频码率、码率模式、封面开关、结果和回退说明 |
| `ExportSession` | 当前一个源视频、可选的一张封面、输出目录、选中的预设及顺序 |
| `ExportJobSnapshot` | 入队时固定的源文件身份、预设参数、封面、工具版本和输出路径 |
| `ExportResult` | 实际输出路径、媒体信息、大小、采用的编码器和结果 |

预设不保存源视频或封面路径，不从名称推断行为。封面可复制到该批任务缓存以避免被编辑；大视频不强制完整复制，任务开始前核对文件长度和修改时间，源文件变化时拒绝继续并要求重新探测。

### 4.2 处理流程

先用 ffprobe 读取结构化 JSON，再解析为模型；使用正式 JSON 解析器，不抓取面向人阅读的诊断文本。[ffprobe 文档](https://ffmpeg.org/ffprobe.html)

读取入口一次只选择一个本地文件，可设置“选择视频后读取信息”，关闭时由“读取媒体信息”按钮触发。首次缺包仍经过宿主确认；媒体读取期间使用不定进度，不编造百分比。模型由插件实例持有，切换工具或设置页不取消读取，返回可见原结果；取消按钮和退出才取消操作。专属偏好通过插件设置存储自动保存，读取损坏配置时保留原文件，写入失败可重试。

ffprobe 的非零退出、JSON 截断、坏 JSON 和无视频流分别作为失败；附加封面流不能充当源视频。信息展示区分编码尺寸与显示方向、平均帧率与实际逐帧时序，缺失数值显示未知、无音频显示无音轨。读取前后检查长度和修改时间，变化时要求重读。读取命令不写源文件，租约持有到工具退出和结果处理完成。该信息读取是媒体链路的入口，不代表转码、首帧替换或 GPU 已经完成；当前交付范围以开发台账为准。

预检选中预设、图片、输出位置和工具，创建不可变任务快照，按顺序调用 FFmpeg；GPU 偏好同样在整批开始时固定，运行中修改设置只影响下一批。每个任务对应一个输出文件；VBR 两次按顺序运行两次受管理的进程，任一时刻最多一个编码进程。

FFmpeg 通过 `-progress pipe:1` 输出可解析的键值进度，错误输出另行记录。进度结束不自动等于成功，还要等待进程退出、校验输出并提交文件。[FFmpeg 文档](https://ffmpeg.org/ffmpeg.html)

每项导出代码由插件内 ExportPlan、ExportProgress、VideoExporter 承担：通过 API 1.5 stdout 回调有界组行，解析 `out_time_us`；输出校验/提交前百分比最多 99。插件模型持有单批次，申请依赖前快照所有勾选预设。媒体读取、依赖准备和参数校验仍为入队前预检，在插件页显示状态和取消；失败或拒绝安装不建公共任务。预检成功后通过 API 1.6 QueueBatchAsync 一次登记整批，再逐项等待 RunAsync 完成；某项失败继续，取消等待项跳过，取消整批停止当前及后续项。包租约覆盖整批，封面以只读共享锁固定、每项另作临时快照；源文件每项检查身份。宿主只提供通用摘要和取消，不引入媒体专属任务服务。

输出先写同一目标文件系统上的任务专属临时文件，显式指定容器或保留正确扩展名。校验后以不覆盖方式提交为 `原文件名_预设名.扩展名`，例如 `旅行_高清.mp4`；名称取本批次预设快照，仅用于文件名，不参与编码参数解析。控制字符和 Windows 文件名非法字符替换为下划线，去除首尾空白和尾部点；清洗后为空的预设名使用“预设”。超长名称保守截短，预设部分最多 80、组合主干最多 200 个 UTF-16 字符，为扩展名和冲突后缀留空间。已有同名文件或目录时依次追加 `_2`、`_3`，并发提交同样禁止覆盖。取消或失败只清理该任务创建的临时产物，不能清理整个用户输出目录。

### 4.3 编码与尺寸

导出页主要参数为输出格式、码率模式、视频码率（Mbps）、音频码率（kbps）。GPU 偏好放在插件设置，不把硬件品牌或 H.264 等编码器名称作为用户必选项。VBR/CBR 表示可变/固定码率，和 CFR/VFR 帧率概念分开；选择码率模式不强制改变源视频帧率。

输入选择/拖放不按扩展名白名单阻拦，由 ffprobe/FFmpeg 识别实际内容。输出使用插件内明确的格式组合，而不是只修改后缀：MP4/MKV/MOV/TS 配 H.264 + AAC，WebM 配 VP9 + Opus。它们是已接入的参数映射，真实可播放性、色彩和码率仍待验收，不宣称任意文件/所有 FFmpeg 容器均已支持。

- VBR 一次：使用目标平均码率进行一次编码。
- VBR 两次：使用软件编码器，先完整分析、再读取同一任务的统计文件编码。第一遍不写视频/音频文件，两遍均使用相同视频滤镜及首帧规则，分别映射到总进度的前后半段；取消第一遍不会启动第二遍。统计文件在独有事务目录，成功、失败、取消均清理。
- CBR：设置目标、最小、最大码率及 VBV 缓冲，并使用对应编码器的固定码率控制；x264 使用 filler，不给 MP4 写入不兼容的 nal-hrd=cbr 信令。这是视频编码码率控制，不保证容器每秒字节数完全恒定，也不把音频和容器开销冒充视频码率。

仍映射首个非附加封面视频流与所有音轨；每条音轨分别使用指定音频码率，估算包含音轨数量。导出限制为可识别的 8 位像素格式、逐行和直角旋转素材；解析 color_space/color_range 并拒绝明确 HDR、广色域、高位深或未支持的色彩范围。色彩标记缺失或 unknown 的 8 位输入按普通 SDR 假设处理，不代表已经证明其色彩正确。当前滤镜使用 FFmpeg 自动颜色协商，BT.709、full-range 素材与彩色封面的首帧/后续色彩仍需用户验证；信息提取不受这些导出限制。

分辨率使用明确宽高或保持源尺寸。普通视频画面的工程默认是保持比例、必要时补边，不能把封面的居中裁剪规则误用到整段视频。先处理旋转元数据和实际显示方向，再确定各版本输出尺寸；校验编码器要求的尺寸倍数。

首版不额外增加复杂剪辑、字幕编辑或 HDR 调色工具。对当前处理链不能可靠支持的素材明确报错；不能默默丢失色彩信息后声称已支持。

### 4.4 第一帧替换

封面针对各任务的最终输出宽高分别适配。使用 FFmpeg 的缩放、裁剪和滤镜能力实现，避免自行编写图像重采样或编码器。[FFmpeg 滤镜文档](https://ffmpeg.org/ffmpeg-filters.html)

替换的定义是：输出第一张实际显示的视频画面来自封面，之后画面对应原视频后续帧，时间轴、时长和音频保持一致。不把图片插在原视频前面，也不将其覆盖在固定的一秒或数秒区间。

开启该功能需要走解码、滤镜、编码处理路径，不能靠视频流直接复制完成。具体滤镜图在 M3 用合成测试视频验证后定稿，覆盖 CFR、VFR、竖屏、旋转和不同图片比例；不把未经运行的长命令作为已可用方案。

当前候选滤镜按输出尺寸缩放/补边主画面，封面居中裁剪并与黑底合成去除透明度，仅在主流 `n=0` 时覆盖；无固定秒数或插入片头。使用 `copyts/start_at_zero`、`fps_mode passthrough` 和滤镜时间基保留时序，封面复制到本次临时目录以固定输入。源码已接入，CFR/VFR、首帧像素、后续帧和音画同步仍待用户运行验证。

### 4.5 GPU 编码

GPU 支持在首版范围内。插件根据包内编码器、本机设备和驱动建立能力列表，例如 NVIDIA NVENC、Intel QSV、AMD AMF 对应的可用实现；不能仅因列表里有名字就标记可用。

通过短样本执行验证选定的容器、编码器、分辨率与滤镜链。滤镜可能在 CPU 上完成再送到 GPU 编码，因此“GPU 编码”不承诺整条处理链都在 GPU 上，也不承诺一定更快。

插件设置提供自动保存的“GPU 加速”开关，默认关闭。开启后，H.264 单次 VBR/CBR 依次检查 NVIDIA NVENC、Intel QSV、AMD AMF：以当前滤镜、尺寸和容器试编码前 8 帧，每次 45 秒超时；可用时才进入完整导出。未建立通用硬件调度或全局能力缓存。

用户已确认自动回退 CPU 并显示原因：没有通过检查的硬件、尚无 GPU 路径的格式、VBR 两次均使用软件编码；GPU 完整导出返回失败时，清理本任务半成品并最多重试一次 CPU。取消不会触发回退。卡片保留本次使用方式或回退原因，不能在回退后仍显示 GPU 成功。设置只表达偏好，不承诺所有格式/设备均可硬件加速。

VBR 两次指文件级完整分析与第二遍编码；NVENC multipass 是逐帧内部处理，不能冒充同一种两次编码。当前 WebM 使用软件 VP9；没有实际设备证据时继续标记相应 GPU 后端未验证。[FFmpeg 硬件选项](https://ffmpeg.org/ffmpeg.html#Advanced-Video-options)

### 4.6 输出大小估算

对于设置平均码率的视频和单音轨，初步估算为：

```text
estimatedBytes = durationSeconds * (videoBitsPerSecond + audioBitsPerSecond) / 8
estimatedMB = estimatedBytes / 1_000_000
```

无音频时音频项为 0；缺少时长或有效码率时显示无法估算。MB 与 MiB 不混用，用户输入的 Mbps/kbps 转换为明确的 bit/s。估算不包含可靠的逐文件容器开销模型，不保证编码器严格达到设置值。预设不包含 `targetFileSize` 字段。

### 4.7 串行、取消与恢复

视频插件的全部转码任务最大并发为 1，重复提交也不能绕过这一约束。一次提交对选中预设拍摄不可变参数快照。取消整批时先阻止后续任务启动，再停止当前任务；某项运行失败则记录错误并继续余项。

页面只订阅任务状态和提交操作，不拥有转码进程；切页或隐藏窗口不取消任务。有限任务服务提供公共状态，视频插件执行自己的串行策略。

任务状态同时展示于插件卡片和宿主“日志 → 任务进度”；宿主页可取消单项或整批、查看结果并返回工具，切页不终止队列。整批一次登记后才逐项执行，取消不会遗漏尚未开始的版本。执行回调正常返回意味着真实输出已校验并提交，迟到取消不撤销成功或清空结果路径。

宿主在 `<DataRoot>/Data/tasks.json` 保存活动任务及最近 100 条终态摘要，重启将非终态标为 Interrupted，供用户返回工具重新提交。摘要不包含视频参数或可恢复进度，不自动重试、不续转码，也不删除崩溃遗留输出。损坏摘要保留并阻止新任务执行，宿主任务页提供保存重试。显式退出有活跃公共任务时先确认；系统退出跳过确认并有界停止，只处理本应用创建的进程树。入队前的读取/依赖准备仍由插件取消和退出生命周期管理，不出现在公共任务列表。

### 4.8 参数、路径与日志

通过宿主进程服务传入独立参数，不拼接 shell 命令。滤镜字符串仍有 FFmpeg 自身转义规则，不能因为使用 ArgumentList 就省略验证；优先将封面作为独立输入文件。工具版本、路径与租约由宿主解析，不随系统 PATH 或终端当前目录变化。

源视频和输出目录属于用户选择的路径，不随应用数据迁移；输出文件不属于应用缓存，不能被缓存清理删除。日志关联插件和任务，记录工具版本、实际编码器、退出码和必要错误，不记录完整媒体内容。正常请求取消记 INFO，GPU 回退 CPU 记 WARNING，操作失败记 ERROR 并保留异常；未请求的 OperationCanceledException 按失败报告。公共任务状态在宿主“日志 → 任务进度”查看，媒体读取和依赖准备仍为插件预检。

## 5. 工程默认与待验证项

- 某个版本失败后记录错误并继续余项；取消整批时停止当前任务和后续任务。
- GPU 偏好不支持或执行失败时按已确认策略自动回退 CPU，并显示原因；取消不触发回退。
- 普通视频保持比例、必要时补边；封面等比缩放后居中裁剪。两者的规则不同。
- 不增加多源视频队列、并行编码、目标 MB 反算、复杂剪辑、字幕编辑或 HDR 调色工具。
- 需在 M3/M4 定稿并留下实际证据：FFmpeg 包能力、初始容器/编码兼容矩阵、CFR/VFR 首帧替换滤镜图、各 GPU 后端支持范围。候选方案不能记为已支持。

## 6. 验收方法

建议测试素材覆盖：横屏/竖屏、旋转元数据、固定/可变帧率、不同封面宽高比、有音频/无音频，以及中文、空格等文件名。涉及特殊字符路径时验证参数和滤镜输入，不通过 shell 执行用户文本。

布局验收同时覆盖两个功能页的宽/窄窗口、高 DPI、键盘选择与复制、拖入多文件/文件夹/非视频、长元数据与多张预设滚动；功能页切换和宿主离页后返回不得丢失输入、预设或运行进度。输出操作栏检查空路径提示、选择/更改/取消文件夹、长路径省略与悬停、窄窗口换行、忙碌锁定及滚动时始终可达。信息报告检查多音轨、字幕、章节与自定义嵌套元数据均保留。

合成视频使用可辨识的首帧和后续帧，并使用有时间标记的音轨。导出后用 ffprobe 检查真实流信息，抽取首帧及后续帧核对；有损编码使用合理容差或画面特征比较，不能要求像素字节完全相同。

验收首帧替换时同时检查帧时间、帧数或时间戳关系、总时长及音频起点。VFR 素材不以“固定 1/fps 秒”猜测首帧持续时间。预览看起来有封面，或资源管理器显示了缩略图，都不能替代上述验证。

文件大小预估检查计算、单位和显示语义，不以实际文件必须恰好等于预计值作为通过条件。GPU 测试记录显卡、驱动、FFmpeg 版本、编码器和输出信息；对无设备的后端只能标为未验证。

| 验收编号 | 本插件的判定重点 |
| --- | --- |
| A09–A12 | 媒体探测、单视频/单封面限制、可复用预设、名称不参与解析、码率单位与大小预估 |
| A13–A14 | 整条视频队列严格串行、重复提交不能并发、入队参数快照、源文件变化保护 |
| A15–A16 | 首帧替换与不开启替换的版本同时验证；后续画面、时长与音画对应关系不被移动 |

| A19–A20 | 单项/整批取消、失败后余项策略、无遗留进程、无源文件/已有输出覆盖、临时文件只清理自身 |

预检覆盖损坏媒体、缺失信息、未知时长、无音轨、容器/编码不兼容、缺少封面、不可写输出、空间不足及同名冲突。用真实进程、输出流信息、首帧/后续帧和音轨时间证据判定，不能用返回码、文件存在或模拟进度替代。完整状态只更新 [开发验收台账](../DEVELOPMENT.md#acceptance)，本文不另维护一套通过记录。
