# 文件夹版本历史插件

整理日期：2026-11-17。需求、接入设计与验收方法；设计与代码不代表运行验收通过。当前进度只记录在[开发与验收](../DEVELOPMENT.md#current-status)，公共接入遵循[插件开发规范](../PLUGIN_DEVELOPMENT.md)与[软件架构](../ARCHITECTURE.md)。运行验收沿用根 AGENTS 与用户接手测试的约定。

## 1. 定位与需求来源

面向不熟悉 Git 的普通电脑用户，为选定文件夹提供可视化的版本历史，让用户在改错、删错后找回文件。用户继续使用原来的编辑器和文件管理器，不需要学习仓库初始化、暂存、提交、分支等概念。

### 1.1 用户已明确的需求

- 选择一个本地文件夹，为这个文件夹启用版本控制，降低安装工具、初始化和配置的启动成本。
- 通过图形化交互管理文件版本，支持查看历史、对比和回退。
- 文件夹可能混合文本、图片及其他二进制文件，不能只按代码项目设计。
- 能关闭某个文件夹的版本控制。
- 主要受众是普通用户；懂 Git 的开发者并非本插件的主要服务对象。
- 本地历史采用无密码方案，不引入历史库加密、自动生成密码、凭据保存或恢复密钥流程，优先减少使用与维护成本。
- 历史保存在受管理文件夹内部的专用子目录，参考 `.git` 的随目录存放方式；用户不必另选历史位置，不代表使用或接管已有 Git 仓库。

### 1.2 工程建议与首版边界

- 产品名称“文件夹版本历史”，稳定 PluginId 为 `TractorTool.FolderHistory`。
- 添加时提供开启自动保护，用户确认后先完成首次保存，再开始监听；辅以“立即保存”和重要版本。已有手动库升级后保持暂停，不能静默开启后台写入。
- 底层以 Duplicati CLI 本地无加密模式作为首个接入目标；具体版本在实施时锁定，接入要求见第 3 节。
- 首版针对 Windows 本机普通文件与目录、单用户本地历史。当前默认稳定窗口 5 秒、最小保存间隔 60 秒、全部保留；这是可调整的实现默认值，仍需真实规模测试，不是性能保证。
- 停止保护默认保留现有文件和历史；彻底删除历史使用单独操作。

本插件是后续独立业务，不改变宿主原首版 R01–R17 范围，不自动调整现有 M5 验收顺序。

## 2. 面向用户的交互

### 2.1 开启历史保护

1. 点击“添加文件夹”，选择目录。
2. 新库可先填写相对路径排除，再扫描显示文件数量、总大小、历史存放位置及可用空间；遇占用或不支持项目时说明失败并允许修改排除后重试，不能将部分扫描当作完整概览。已有库先核对身份即可关联浏览，不要求当前文件可读；开启保护时再按库内规则核对工作文件。大小为估算，不承诺精确压缩率。
3. 给出可理解的默认规则，排除项可查看和调整。准备外部工具时仍走宿主已有的来源展示、首次确认和下载流程，不绕过依赖授权。
4. 创建第一份历史。完整保存成功后才显示“已保护”；拒绝安装、取消、部分读取失败不能显示成全部保护成功。

日常文件继续留在原位置，插件只新增自己的历史子目录；已有历史时先核对身份与格式再关联。不要把工作文件移动进私有容器，不接管或删除目录中已有的 `.git`、其他软件元数据或用户备份。

### 2.2 日常自动保存与状态

- 主页面显示受保护目录、上次完整保存时间、当前状态、历史占用与“立即保存”。高级技术信息放详情，不要求用户输入命令、仓库格式或分块参数。
- 观察文件变化，在一批修改稳定后合并保存；不为每次磁盘写入生成一个版本。同一目录已有保存任务时，合并后续请求，完成后核对是否仍有变化。
- 界面区分“已保存”“有更改待保存”“正在保存”“已暂停”“保存不完整”“需要处理”。不能仅凭监听器正在运行就显示文件已经安全保存。
- “立即保存”可附加说明；“保留这个版本”将版本标为重要，自动清理不能删除它。自动保存没有内容变化时不堆积重复记录。
- 切页和隐藏到托盘不停止保护；完全退出软件或插件停止后不记录。重新启动检查现状并补做核对，不能声称补回退出期间每一次编辑的中间版本。

调度使用文件系统事件和单次到期等待，不周期轮询目录。稳定窗口与最小间隔同时满足才保存；库内部写入和排除路径不触发捕获。首次确认后后台只获取已安装工具，不反复弹安装确认；工具或目录不可用时显示需要处理，手动重新开启后重新核对。

### 2.3 查看与对比历史

目录概览 → 时间线 → 某次版本的变化列表 → 文件预览/对比/恢复。时间线优先展示时间、说明和“修改 3 个文件、删除 1 个文件”这类摘要；技术 ID 留在详情。

支持选择两个已保存版本比较，并提供文件自身的历史入口。目录比较至少准确列出新增、修改、删除；重命名识别可以作为后续增强，首版可明确显示为删除与新增，不能给出没有依据的重命名结论。

| 内容类型 | 首版建议 | 能力边界 |
| --- | --- | --- |
| 文本、代码、配置 | 有大小限制的逐行对比；保留原始字节供恢复 | 无法可靠识别编码时降级，不为了显示而改写文件编码或换行 |
| 常见图片 | 提供旧版本提取；双图对照可后续增加 | 保存图片历史不等于已实现视觉差异算法 |
| Office、PDF、PSD、视频及未知二进制 | 展示内容是否变化、大小等信息，提取选定版本 | 不承诺解释内部段落、图层或视频帧的语义变化 |

预览只读且有资源上限；不执行历史文件中的程序、脚本或宏。时间戳只是信息，不能单独作为“内容相同”的证据。

文本预览只提取所选文件，每侧最多 256 KiB、1,200 行、每行 4,096 字符，对比矩阵最多 1,000,000 格。识别严格 UTF-8 及带 BOM 的 UTF-16/32，区分行尾和 BOM/编码变化；超限、无效编码或二进制内容改为另存查看，不猜编码。

### 2.4 恢复与回退

提供两种明确操作：**“另存一份”**将选定文件/目录恢复到新位置；**“恢复到原位置”**修改现有目录。两者均支持单个文件与整个目录。

原地恢复的产品要求：

1. 固定目标版本，预览将新增、覆盖和删除的内容；说明只覆盖所选范围，排除项和未受保护文件不因回退被顺带删除。
2. 在改动前完整保留将受影响的当前文件，生成可用的恢复前版本；不能因当前排除规则遗漏即将被覆盖的数据。保护失败则不进入覆盖阶段。
3. 准备并校验恢复内容，记录恢复计划及进度后执行。检查预览之后的新修改，出现冲突时停止并重新处理，不覆盖用户刚写入的内容。
4. 完成后校验实际结果，再报告成功。回退不会删除时间线上较新的版本，用户能再次恢复回来。

“整个目录回退”需要明确处理目标历史中不存在的新文件，不能只覆盖已有文件就称为完整回退；处理范围必须与预览一致。现有引擎的覆盖/删除开关不能替代这些保护。

原地恢复和“另存一份”均只作用于工作文件，不恢复、覆盖或删除专用历史子目录，也不能整体替换受管理根目录；历史中的越界路径或指向该子目录的条目必须拒绝，不能只依靠保存时的排除规则。

多文件原地恢复不承诺文件系统级原子性。取消、进程中断、断电或文件占用后，应保留恢复前数据和操作记录，显示“恢复未完成”，重启后提供检查与恢复入口；未处理完之前暂停该目录自动保存和清理，避免把半恢复状态当作正常版本。

### 2.5 停止保护与清理

- “停止保护”不改动当前文件，停止后续自动记录，保留已有历史供浏览和恢复。已有任务先停止调度并等待或安全取消，不能一边写入一边移除记录。
- “重新开启”核对目录身份与现状，不能只凭旧路径相同就误认同一目录。
- “删除历史”是独立的不可撤销操作，显示影响范围与占用，不删除当前工作文件；有保存、恢复、导出或待处理恢复记录时不可清理相关历史。
- 插件禁用、升级、卸载不能隐含删除用户历史；目录暂时离线、被重命名或找不到也不授权自动清理。

“文件夹设置”提供精确相对路径排除（每行一个文件或目录，不支持通配符）、保留数量和天数。数量与天数均为 0 表示保留全部；两者同时设置时只删除同时超出两条规则的版本，始终保留最新、重要及恢复前保护版本。启用清理规则会明确提示后续自动保存可能执行清理。“管理历史”可预览规则范围；删除全部版本需先解除重要标记并再次确认，暂停保护，保留工作文件及库身份/设置。清理中断只继续此前确认的版本范围，不把重试解释为新的删除授权。

## 3. 技术选型建议

采用“成熟快照引擎 + 插件交互”，首个接入目标是 Duplicati CLI：本地 `file://` 配合 `--no-encryption`，无需密码、云账号或独立服务，复用其备份、版本查询、比较、恢复和清理能力。每版逻辑上是一份完整目录视图；分块、压缩、去重及垃圾回收交给引擎，不自研或重复验证这些内部算法。

只验证插件的实际调用、路径处理和结果判断。若出现确定的接入阻断，再评估 LibGit2Sharp 等备选；不先做新一轮全面选型或多引擎适配平台。

引擎的版本差异列表不等于文本逐行或图片视觉对比，展示层需要独立落实。去重也不保证任何二进制都只保存“小改动”：视频重编码、压缩包重打包或加密文件重写可能改变大量字节。耗时和空间应以真实文件测量，不能只看文件数量或工具返回码。

接入固定一个官方 Windows ZIP，声明精确 Release 标签、附件、SHA256、许可、CLI 相对路径及版本探测参数/输出前缀，复用宿主安装流程。为每库显式指定 `--dbpath`；引擎内容、索引与插件元数据/恢复暂存在专用历史目录内分开存放，不能把任意辅助文件混入引擎内容目录。按固定版本核对命令、过滤规则、输出及退出码，不依赖默认全局索引或交互提示。

官方 CLI 文档提示部分旧版本恢复缺项仍可能返回 `0`。插件须结合完整结果、缺项/错误及实际恢复内容判断成功；参数不被识别、输出截断或部分失败均不能忽略。目录排除必须先于可编辑规则生效，移动后的恢复路径映射见第 4 节。

### 固定版本接入

[插件清单](../../Plugins/TractorTool.Plugins.FolderHistory/plugin.json)锁定官方 `v2.4.0.1_stable_2026-10-07` Windows x64 GUI ZIP 中的 CLI、附件 SHA256 和探测入口。宿主包标识 `Duplicati.CLI/1.0.1` 表示接入配方版本，显示名称注明真实工具版本 `2.4.0.1`；宿主当前只接受三段版本，未因此修改公共框架，也没有新增自有安装源。

安装探测使用 `system-info`，显式指定 `--dbpath=tractortool-probe.sqlite --no-local-db=true`，避免默认数据库定位器创建全局登记文件及对便携 `data` 目录做无关初始化。探测不生成数据库，仍检查真实程序集输出、退出码和截断；不使用 `--allow-insecure-datafolder` 绕过权限检查。保存/修复/恢复本身已显式指定库内索引；真实验收状态统一见[开发台账](../DEVELOPMENT.md#current-status)。

- [引擎适配器](../../Plugins/TractorTool.Plugins.FolderHistory/Processing/DuplicatiEngine.cs)使用本地 `repository/`、显式 `index.sqlite` 和 `temp/`。无加密、SHA256、ZIP；固定版没有通用 JSON 查询接口，读取其原生 `.dlist.zip` 文件表，不解析本地化控制台文本、不另存一份内容数据库。
- `history.json` 记录库身份、格式、已确认版本 ID、原根、说明、重要/恢复保护标记、自动保护与目录规则及待清理范围。schema 1 可读且默认暂停，首次写入升级为 schema 2；旧插件随后会拒绝该格式，不支持将库降级回旧版。工作树保存前后与引擎清单一致才登记版本；失败或取消产生的未登记卷不显示为可用版本。浏览只读取已登记清单，未登记坏卷不能在插件读列表时连带隐藏正常旧版本；有内容变化的保存会先核对全部原生版本文件的命名与完整版本清单，异常时停写，不自动删除或补登记。这不是逐字节扫描全部分块/索引。恢复的版本编号按全部原生卷排序，不能因筛选而改变。正常无变化由插件跳过；引擎允许上传相同内容，以便中断后的重试生成可确认版本。
- 另存始终先在库内提取，并按选定清单核对路径、目录、大小和 SHA256，再向目标父目录下的新目录发布；不将引擎记录的原绝对路径作为写入目标。单项提取用固定版过滤参数限定范围，逐文件复制期间与发布前继续校验，已有目标不覆盖。
- 原位恢复使用插件内的持久操作记录：先暂停保护、生成不受可编辑排除影响的完整保护版本并标重要，实际提取校验保护版本可恢复，再提取目标、重验预览、保存步骤。仅有可读文件清单不能证明保护内容完好，包括复用无变化的上次版本。原文件移入事务撤销区，目标文件无覆盖发布；中断保留材料，继续/撤销均核对当前内容，不覆盖后来出现的占位文件。完成后校验所选范围，清理已核实的临时材料并保留小型操作记录，失败清理记录 Warning。自动保护保持暂停，由用户重新开启。
- 清理调用原生 `repair`、`delete`/`compact`，使用独立索引核对版本编号和保留清单；不自行删除内容块。有效的未登记 partial 卷只校验和保留，仍计入原生编号；存在未登记卷时“删除全部”明确拒绝，不扩展用户已确认范围。只读预检在登记清理意图之前，尚未开始删除的失败不锁死正常库；真正开始后保留确认范围、保留清单摘要及原生索引以继续回收，缺失/损坏材料不静默补建为成功。
- 固定版对“没有普通文件”发出 `NoFilesInBackup`，收紧 SQLite 文件权限失败则发出 `SQLiteFilePermissionError`。保存、索引修复和另存共用官方精确 ID 兼容这两项；权限项在宿主保留 Warning，说明历史仍受所在目录权限控制，不宣称已修复上游 ACL，不提升权限、不设置全局环境或关闭安全检查。另存仅在已选清单没有普通文件时增加一个明确 ID：只有根目录为 `NoFilesOrFoldersRestored`，含子目录为 `NoFilesRestored`；含普通文件的版本不允许这两项。无文件场景仍须核对实际完整目录结构。退出码 0 不能单独判定成功：还要求无 stderr、无输出截断、操作日志没有未知警告/错误且完整清单匹配；诊断不完整或未知格式拒绝确认成功。
- 每次引擎调用在历史库 `temp/` 写独立诊断日志，仅额外包含上述权限项的固定日志标记，有界读取后汇总到公共日志。控制台文本不带稳定 ID，不用本地化错误正文做分类，也不读取引擎私有 SQLite 表。CLI 失败或诊断不完整时保留本次日志；CLI 检查通过并转存必要详情后只清理本次文件，清理失败记录 Warning。随后清单/工作树校验仍可能失败且不登记，此时已转存的详情从公共日志查看。真实参数效果、空目录及恢复接入仍须按第 7 节验收。
- 只保存普通文件的原始内容、名称和目录结构；不承诺 ACL、ADS、硬链接关系或应用一致性。链接、重解析点、离线占位等拒绝处理。失败的提取暂存可能保留在历史库内，未作为可用版本；不为回收空间擅自删除未知材料。

`file://` 保证历史目的地为本地目录，不等于工具完全无网络行为：上游 CLI 默认可能发送启动/使用统计，便携模式还可能在工具目录保存辅助信息。插件未修改全局环境或用户 Duplicati 配置；来源说明见 [NOTICE](../../Plugins/TractorTool.Plugins.FolderHistory/NOTICE.md)。当前进程接口无单次环境覆盖，若后续要求强制关闭这类统计，应先交架构侧讨论；不能在插件内绕开公共进程服务。真实安装、首次探测的 15 秒限制及断网行为须单独验收。

## 4. 存储、恢复与框架边界

### 4.1 数据归属

**已确认采用随工作目录存放的方式。** 每个受管理目录有自己的隐藏历史子目录，名称暂用 `.tractortool-history`，不要求用户另选历史盘或维护外置库。

```text
D:\工作\设计稿\
  文档.docx
  图片.png
  .tractortool-history\    # 历史内容、库元数据、索引和恢复记录
```

- 工作文件和历史库都属于用户文件。库身份、目录规则、保护启停状态、重要版本标记及未完成恢复记录随历史保存；若有引擎索引，应可从库重建，不另造无法核对的第二份历史数据库。
- 宿主 DataRoot 中只保存本插件的全局偏好与已关联目录列表；引擎仍由宿主放入 `Packages`，插件程序仍位于 AppRoot 的 `Plugins`。首版拒绝受管理目录与 AppRoot/DataRoot 互含；启动、重新关联及写入前重新核对，发现新的重叠就停写提示，不承诺宿主会自动识别受保护目录。
- 专用子目录及全部后代必须从工作文件扫描、变化监听、版本对比和所有快照中强制排除，包括恢复前保护；用户包含规则不能重新纳入。排除不依赖隐藏属性。否则会把历史再次保存进历史，并由自身写入持续触发保存。临时恢复文件也放在被排除的专用范围内。
- 创建时核对专用名称是否已被文件/目录占用、身份是否有效及路径是否经过链接；未知同名内容、损坏或不兼容的库不覆盖、不自动重建。只保护确认为本插件拥有的历史目录，不把用户其他隐藏目录一概忽略；首版拒绝互含的受管理目录，避免父子库交叉纳入。
- 插件更新、回退、禁用及卸载保留目录内历史；回退只还原宿主管理的全局偏好和目录列表，不让历史或删除保护倒退。旧插件不认识库格式时停止写入和清理，不能强行降级库。
- 修改软件 DataRoot 只迁移本插件的全局偏好和目录列表，工作文件及内置历史库原地保留。配置重置或回退后列表丢失时，重新添加原目录须识别已有库，不能覆盖建新库。
- 停止任务后移动或完整复制整个工作目录（包含隐藏历史目录），历史一起带走。重新添加时验证库身份，库及索引路径从当前根解析；每版保留必要的原根对应关系，比较按相对路径，恢复先提取到暂存区、校验后映射到当前根，不直接写回工具记录的旧绝对路径。多个已关联副本若有相同库 ID，提示冲突并暂停自动写入，由用户明确关联，不静默合并或替换。

历史库不进入宿主管理的数据目录，无需为其预建公共生命周期接口。接入检查须覆盖目标在源子目录内的排除、移动后重连和恢复映射；实际不支持时报告阻断，不悄悄改成外置存储。

**限制：删除整个工作目录、专用历史目录或丢失该磁盘，历史也会一起丢失。** 软件只能报告库缺失，不能凭配置找回历史；不得将此方案宣传为防整目录丢失或磁盘故障的独立备份。

### 4.2 无密码与可恢复性

本地历史不加密，不设置或隐式生成仓库密码，也不要求用户备份恢复密钥。无密码不等于没有访问边界：沿用 Windows 文件权限，能读取历史库的人也能读取其中的旧内容。首版不另建加密或密钥管理功能。

恢复依赖完整历史库、必要的库元数据及兼容引擎，不应依赖本机秘密或不可重建的列表索引。全新插件配置下应能重新关联已有库并恢复原始文件；独立索引遗失时使用引擎已有的重建能力。无密码流程无需扩展公共 stdin/环境变量接口。

### 4.3 复用现有公共能力

| 职责 | 复用入口 / 归属 |
| --- | --- |
| 页面与设置 | `IPluginUiModule`、`IPluginPageRegistry`，沿用公共主题与控件 |
| 变化观察与调度 | 插件的 `IPluginBackgroundService`，不绑定页面 Loaded/Unloaded |
| 保存、恢复、检查与清理 | 公共有限任务记录进度、取消和结果，业务参数与一致性检查归插件 |
| 工具获取 | `IExternalPackageService` / `IPackageLease`，租约覆盖进程和输出读取 |
| 命令执行 | `IProcessRunner`，使用结构化参数与有界输出解析，不通过 shell 拼接命令 |
| 配置与日志 | `IPluginSettingsStore`、`IAppPaths`、`IAppLog`，不逐文件刷屏或记录内容/凭据 |

**已核对的接入边界：现有接口足以开始插件开发，未发现需要预改框架的确定缺口。** [ProcessRequest](../../TractorTool.Contracts/Processes/IProcessRunner.cs) 支持参数、工作目录、有界输出及 stdout 分块回调，取消/超时由现有进程服务清理进程树。插件自行拼接跨块文本、识别截断，并将二进制恢复到文件；强停不保证引擎完成提交，须保留恢复材料并核对库及操作状态，公共任务仍遵循宿主的取消/失败语义。

其余接口事实以 [PluginContracts](../../TractorTool.Contracts/PluginContracts.cs)及[插件接入规范](../PLUGIN_DEVELOPMENT.md)为准。文件监听、版本调度、对比与恢复策略均归插件；若实现中出现必须修改宿主、Core、Contracts 或公共 UI 的真实缺口，按根 AGENTS 约定先停止该项修改并交架构侧分析。

## 5. 可靠性与首版边界

| 情况 | 必须落实的行为 |
| --- | --- |
| 变化监听 | 文件系统事件只作为“需要核对”的信号；合并重复事件，启动、重连、缓冲溢出后重新核对。不能把事件列表当作完整目录事实，也不每个事件启动一次工具 |
| 持续写入 | 设定稳定窗口、最小保存间隔和重试/延后策略；变化仍在持续时显示待保存，不宣称每次编辑均已捕获。具体数值需测量后定案 |
| 源目录离线/消失 | 显示不可用，不主动清理历史；确认专用历史目录缺失时明确提示，不能把暂时读不到解释为“全部文件已删除”并生成空版本或冒充原库 |
| 部分失败 | 文件被占用、拒绝访问、读取中变动时报告缺项；不完整结果不可作为最新完整版本或恢复前保护成功的依据 |
| 引擎警告与诊断 | 仅兼容固定的无普通文件/SQLite 权限收紧警告；权限项保持可见，其他警告、stderr、截断或无法读取完整诊断阻止成功。未登记异常卷保留并阻止新保存；已登记版仍可分别读取，另存必须通过引擎结果与实际字节校验 |
| 同时操作 | 同一目录的保存、原地恢复和历史清理互斥；恢复期间暂停自动捕获，完成后重建观察基线。跨目录并发设合理上限 |
| 空间不足 | 预估首次保存/恢复临时空间，显示占用与失败；不以释放空间为由删除工作文件或未授权的重要历史 |
| 版本保留 | 重要版本及待处理恢复使用的版本不可自动清理；显式核对引擎默认保留策略与维护任务，规则可见、可解释。规则或重要标记损坏时停止自动删除。先确认要删除的版本，再由引擎回收数据，不能自行递归删除内容块 |
| 完整性 | 校验快照可读取及恢复内容；识别损坏、未知格式、工具错误与输出截断，不能凭进程退出或存在一个历史条目就报成功 |
| 路径边界 | 规范化路径并检查大小写、目录重叠、相对路径越界、链接/重解析点与恢复目标冲突；强制排除和保护专用历史子目录；恢复和删除前重新确认目标，不能只在添加目录时检查 |

首版建议支持普通文件内容、文件名、目录结构（含空目录）与经过验证的必要属性。Windows ACL、ADS、硬链接、稀疏文件、符号链接、云端占位文件、网络盘及超长路径分别列出支持范围；不支持时明确提示或拒绝，不静默跳过后声称完整保护。

运行中的数据库、虚拟机及多文件工程不因“创建快照”这个名称就具有同一时刻的一致性。普通逐文件读取不能保证应用一致；首版提示停止相关写入后保存。VSS、应用协作快照、管理员服务和内核驱动不自动纳入范围。

暂不开发分支/合并、Git 远程互通、云同步、团队协作、通用二进制语义对比、全天候独立 Windows 服务或新的公共备份平台。同盘历史用于误改/误删恢复，不能宣传为防硬盘损坏的异地备份。

## 6. 实施顺序与交接要求

1. **直接开始插件接入**：沿现有插件工程模式建立入口、配置与引擎调用，锁定第 3 节所需版本和命令信息，不新增框架服务。产品名称、稳定 ID 和普通参数在实现时确定；自动保存的建议不改写成既有验收结果。
2. **小范围接入检查**：复用插件自己的调用路径，用一组临时文本、图片、二进制及空目录保存两个版本、查询变化并另存恢复，核对字节及目录清单；重点检查历史子树排除、移动后的路径映射、失败与取消结果。验证对象是新增接入逻辑，不另建引擎验证平台或重测存储算法；检查结果不代表完整插件验收。
3. **恢复可靠性**：完成恢复前保护、范围预览、并发写入冲突、失败/取消/重启后的处理，再开放原地回退。
4. **普通用户交互**：完成时间线、变化列表、文本对比、自动调度、立即保存、重要版本、停止/重新开启和清理；是否默认开启自动保存按定案落实，不能只做手动演示就宣称满足自动保护。
5. **独立交付**：按公共规范独立构建插件、校验宿主未变化，记录真实安装与运行结果；后续 Review 重点检查数据损失路径、任务生命周期、重复实现和悬空代码。

实施不要求新增所有可能用到的模块。按实际职责组织少量插件代码，优先复用引擎和已有公共能力。后续 Agent 不得把本文的设计与验收清单直接勾为完成；实际结果回填开发台账，详细证据按仓库约定归档。

## 7. 验收方法

以下是随实现逐项完成的验收要求，不作为开始开发前的集中测试门槛，也不代表已执行结果。使用临时样本和隔离数据根；应用、引擎和检查程序的运行仍遵循用户接手测试的约定，不在真实用户目录注入故障。

| 范围 | 验收要求 |
| --- | --- |
| 零手工环境准备 | 未安装 Git/引擎的 Windows 环境，通过宿主依赖流程完成首次保护；拒绝/断网/校验失败均不产生虚假的成功状态 |
| 权限兼容与失败详情 | 普通用户下仅 `SQLiteFilePermissionError` 时内容校验通过才登记，并在宿主汇总 Warning；与任意其他警告混合时仍拒绝。覆盖首次保存、索引重建和无本地库另存，诊断缺失/超限、stderr 与进程输出截断均明确失败；不能通过只看退出码或模拟日志宣称真实接入通过 |
| 混合内容 | 文本、多编码、图片、二进制、大文件和空目录经多次增删改后可恢复；逐文件哈希及目录清单一致，不仅验证文件存在 |
| 历史对比 | 两版本的新增/修改/删除与实际操作一致，覆盖同大小/同时间戳但内容变化的情况；文本增删行正确，未知二进制明确降级，原始内容和换行未被预览改写 |
| 自动调度 | 连续保存、批量复制、删除重建、监听事件溢出/丢失、重启后补查不遗漏最终状态；无变化不重复保存，不出现任务洪峰 |
| 恢复范围 | 单文件与整目录、原地与另存均验证；处理新增文件符合预览，排除项和无关文件不被删除，历史里的后续版本仍可用 |
| 恢复失败 | 保护失败、覆盖前新修改、文件占用、近满盘、取消/强制中断后保留恢复材料；重启可明确处理未完成状态，不能误报成功 |
| 目录身份 | 重命名、移动、盘符变化、暂时离线、同路径换目录不清空旧历史，重新关联有明确确认；重叠/链接路径不越界 |
| 关闭与清理 | 停止保护、禁用/卸载插件均保留当前文件与历史；删除历史不触及工作目录，重要版本和活动操作的引用不会被回收 |
| 无密码与重建 | 创建、保存、查看及恢复均无密码/密钥流程；全新插件配置下可重新关联已有库并按原始字节恢复；引擎若使用独立索引，验证其重建 |
| 目录内历史库 | 库及索引/临时文件不被快照、对比或监听当作工作文件；包含规则不能解除排除；原地回退及另存不覆盖/删除历史目录；同名未知内容、链接及嵌套保护被拒绝 |
| 历史库生命周期 | DataRoot 迁移/重置、插件更新/回退/卸载不删除或倒退目录内历史；列表丢失可重新关联。完整移动/复制后可接续保存、按相对路径比较并在当前根恢复，不写旧路径；同 ID 副本不静默合并，未知格式不写入或清理；库缺失明确报告，不自动建空库冒充旧历史 |
| 生命周期 | 保存/恢复期间切页、隐藏到托盘继续工作；显式退出按宿主策略取消并记录结果，无遗留进程、锁或悬空监听 |
| 性能与可理解性 | 大文件、多小文件、已压缩/加密样本分别记录耗时、CPU/内存和新增磁盘占用；普通用户可看懂状态并完成一次找回，不能用模拟进度替代真实操作 |
