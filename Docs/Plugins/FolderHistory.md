# 文件夹版本历史插件（设计交接）

整理日期：2026-11-15。面向后续开发 Agent 的需求与设计依据；文中的建议不代表已有实现或运行验收。当前进度只记录在[开发与验收](../DEVELOPMENT.md#current-status)，公共接入遵循[插件开发规范](../PLUGIN_DEVELOPMENT.md)与[软件架构](../ARCHITECTURE.md)。本轮授权仅整理文档，后续开发由用户另行安排。

## 1. 定位与需求来源

面向不熟悉 Git 的普通电脑用户，为选定文件夹提供可视化的版本历史，让用户在改错、删错后找回文件。用户继续使用原来的编辑器和文件管理器，不需要学习仓库初始化、暂存、提交、分支等概念。

### 1.1 用户已明确的需求

- 选择一个本地文件夹，为这个文件夹启用版本控制，降低安装工具、初始化和配置的启动成本。
- 通过图形化交互管理文件版本，支持查看历史、对比和回退。
- 文件夹可能混合文本、图片及其他二进制文件，不能只按代码项目设计。
- 能关闭某个文件夹的版本控制。
- 主要受众是普通用户；懂 Git 的开发者并非本插件的主要服务对象。

### 1.2 本文建议，尚待开发前验证或定案

- 产品名称暂用“文件夹版本历史”，可用“文件夹时光机”解释用途；显示名称与稳定 PluginId 在建工程前确定。
- 默认自动保存历史，辅以“立即保存”和“保留这个版本”。这是根据普通用户定位提出的建议，不把此前“手动保存优先”的方案作为定案。
- 底层优先验证 Kopia；restic 为备选。用户没有指定引擎，不为同时支持多个引擎预建抽象平台。
- 首版针对 Windows 本机普通文件与目录、单用户本地历史；具体自动保存间隔、排除规则、保留期限与空间限额不在本文虚构为已确认值。
- 停止保护默认保留现有文件和历史；彻底删除历史使用单独操作。

本插件是后续独立业务，不改变宿主原首版 R01–R17 范围，不自动调整现有 M5 验收顺序。

## 2. 面向用户的交互

### 2.1 开启历史保护

1. 点击“添加文件夹”，选择目录。
2. 扫描并显示文件数量、总大小、历史存放位置、可用空间和无法纳入的项目；明确这是估算，不能承诺精确压缩率。
3. 给出可理解的默认规则，排除项可查看和调整。准备外部工具时仍走宿主已有的来源展示、首次确认和下载流程，不绕过依赖授权。
4. 创建第一份历史。完整保存成功后才显示“已保护”；拒绝安装、取消、部分读取失败不能显示成全部保护成功。

用户目录保持原样，日常文件继续留在原位置。不要把工作文件移动进私有容器，不接管或删除目录中已有的 `.git`、其他软件元数据或用户备份。

### 2.2 日常自动保存与状态

- 主页面显示受保护目录、上次完整保存时间、当前状态、历史占用与“立即保存”。高级技术信息放详情，不要求用户输入命令、仓库格式或分块参数。
- 观察文件变化，在一批修改稳定后合并保存；不为每次磁盘写入生成一个版本。同一目录已有保存任务时，合并后续请求，完成后核对是否仍有变化。
- 界面区分“已保存”“有更改待保存”“正在保存”“已暂停”“保存不完整”“需要处理”。不能仅凭监听器正在运行就显示文件已经安全保存。
- “立即保存”可附加说明；“保留这个版本”将版本标为重要，自动清理不能删除它。自动保存没有内容变化时不堆积重复记录。
- 切页和隐藏到托盘不停止保护；完全退出软件或插件停止后不记录。重新启动检查现状并补做核对，不能声称补回退出期间每一次编辑的中间版本。

### 2.3 查看与对比历史

目录概览 → 时间线 → 某次版本的变化列表 → 文件预览/对比/恢复。时间线优先展示时间、说明和“修改 3 个文件、删除 1 个文件”这类摘要；技术 ID 留在详情。

支持选择两个已保存版本比较，并提供文件自身的历史入口。目录比较至少准确列出新增、修改、删除；重命名识别可以作为后续增强，首版可明确显示为删除与新增，不能给出没有依据的重命名结论。

| 内容类型 | 首版建议 | 能力边界 |
| --- | --- | --- |
| 文本、代码、配置 | 有大小限制的逐行对比；保留原始字节供恢复 | 无法可靠识别编码时降级，不为了显示而改写文件编码或换行 |
| 常见图片 | 提供旧版本提取；双图对照可后续增加 | 保存图片历史不等于已实现视觉差异算法 |
| Office、PDF、PSD、视频及未知二进制 | 展示内容是否变化、大小等信息，提取选定版本 | 不承诺解释内部段落、图层或视频帧的语义变化 |

预览只读且有资源上限；不执行历史文件中的程序、脚本或宏。时间戳只是信息，不能单独作为“内容相同”的证据。

### 2.4 恢复与回退

提供两种明确操作：**“另存一份”**将选定文件/目录恢复到新位置；**“恢复到原位置”**修改现有目录。两者均支持单个文件与整个目录。

原地恢复的产品要求：

1. 固定目标版本，预览将新增、覆盖和删除的内容；说明只覆盖所选范围，排除项和未受保护文件不因回退被顺带删除。
2. 在改动前完整保留将受影响的当前文件，生成可用的恢复前版本；不能因当前排除规则遗漏即将被覆盖的数据。保护失败则不进入覆盖阶段。
3. 准备并校验恢复内容，记录恢复计划及进度后执行。检查预览之后的新修改，出现冲突时停止并重新处理，不覆盖用户刚写入的内容。
4. 完成后校验实际结果，再报告成功。回退不会删除时间线上较新的版本，用户能再次恢复回来。

“整个目录回退”需要明确处理目标历史中不存在的新文件，不能只覆盖已有文件就称为完整回退；处理范围必须与预览一致。现有引擎的覆盖/删除开关不能替代这些保护。

多文件原地恢复不承诺文件系统级原子性。取消、进程中断、断电或文件占用后，应保留恢复前数据和操作记录，显示“恢复未完成”，重启后提供检查与恢复入口；未处理完之前暂停该目录自动保存和清理，避免把半恢复状态当作正常版本。

### 2.5 停止保护与清理

- “停止保护”不改动当前文件，停止后续自动记录，保留已有历史供浏览和恢复。已有任务先停止调度并等待或安全取消，不能一边写入一边移除记录。
- “重新开启”核对目录身份与现状，不能只凭旧路径相同就误认同一目录。
- “删除历史”是独立的不可撤销操作，显示影响范围与占用，不删除当前工作文件；有保存、恢复、导出或待处理恢复记录时不可清理相关历史。
- 插件禁用、升级、卸载不能隐含删除用户历史；目录暂时离线、被重命名或找不到也不授权自动清理。

## 3. 技术选型建议

推荐先验证“成熟快照引擎 + 插件交互”。每个版本在逻辑上是一份完整的目录视图，底层复用相同内容块；插件不自行实现分块、压缩、对象库及垃圾回收。

| 路线 | 适用性与结论 |
| --- | --- |
| Kopia | 优先候选：已有文件/目录快照、内容去重、压缩、本地历史、单文件恢复及 Windows 命令行程序；插件负责用户交互、调度和安全恢复策略 |
| restic | 同类备选；仅在 Kopia 的可靠性或集成验证不满足要求时再比较，首版不同时维护两套后端 |
| LibGit2Sharp / 内置 Git | 能省掉用户手工安装和初始化 Git；若未来核心需求变为代码分支、合并与 Git 互通再评估，不能误称 Git 不支持二进制 |
| 自研存储引擎 | 本需求没有必须自研的证据，不作为默认路线 |

Kopia 的快照差异列表不等于文本逐行或图片视觉对比，展示层需要独立落实。去重也不保证任何二进制都只保存“小改动”：视频重编码、压缩包重打包或加密文件重写可能改变大量字节。耗时和空间应以真实文件测量，不能只看文件数量或工具返回码。

Kopia 官方有 Windows ZIP，适合核对现有 GitHub 依赖安装路线。实施前固定工具版本、附件、SHA256、命令协议与许可；本文不把调研时的发布版本写成永久依赖配置。

## 4. 存储、凭据与框架边界

### 4.1 数据归属

- 工作文件仍属于用户选择的原目录；历史是独立持久数据，不是缓存或可清理的工具包。
- 插件配置、目录身份、规则和恢复记录按稳定 PluginId 隔离；工具由宿主放入 `Packages`，插件程序仍位于应用目录的 `Plugins`。
- 默认数据位置遵循宿主 DataRoot 约定。历史存储必须在被保护目录之外，也不能通过链接或重叠选择被另一个受保护目录递归纳入。自定义历史盘的位置与生命周期需要先完成下述框架核对，不擅自另建全局数据根。
- 首版建议每个受保护目录对应独立的历史存储，简化停止、删除和故障隔离；暂不追求跨目录去重。目录身份使用稳定 ID，路径变化后可重新关联，不能把盘符或路径字符串作为唯一身份。
- 引擎历史是内容与目录树的依据；插件只保存必要的用户规则、重要版本标记和操作记录。若需列表索引，应可重建，不能制造第二份无法核对的文件历史数据库。

**开发前必须核对宿主升级/回退与数据迁移。** 当前宿主更新插件前会备份完整插件数据，回退前保留新版数据到 `before-rollback`。把大型历史库直接放进普通插件数据目录，可能造成升级复制大量历史，并使回退后的配置/历史视图与新产生的数据不一致。需明确容量成本、历史兼容性和新历史保留/重新关联方式；不能只图少写代码就让用户历史随插件版本倒退。外置存储也必须说明迁移、离线、卸载和凭据恢复行为，不默认宿主会处理它。

### 4.2 凭据与可恢复性

Kopia 的历史存储使用加密。建议插件生成随机凭据并使用 Windows 安全凭据存储，让日常用户无需填写密码；同时提供受控的恢复凭据导出/导入，解释重装系统或换电脑时需要它。历史文件与恢复凭据两者齐备，才构成可独立恢复的材料。

凭据不得放进日志、命令行参数、普通配置明文或公开重连字符串。当前 `ProcessRequest` 有参数、工作目录和输出回调，但没有独立的 stdin/环境变量注入契约；需先验证引擎支持的凭据获取方式能否在既有接口内安全使用。不能通过全局修改进程环境、另建未受管理进程或临时明文密码文件绕过该问题。若确需公共能力扩展，先提交能力缺口与影响，由用户安排架构分析。

### 4.3 复用现有公共能力

| 职责 | 复用入口 / 归属 |
| --- | --- |
| 页面与设置 | `IPluginUiModule`、`IPluginPageRegistry`，沿用公共主题与控件 |
| 变化观察与调度 | 插件的 `IPluginBackgroundService`，不绑定页面 Loaded/Unloaded |
| 保存、恢复、检查与清理 | 公共有限任务记录进度、取消和结果，业务参数与一致性检查归插件 |
| 工具获取 | `IExternalPackageService` / `IPackageLease`，租约覆盖进程和输出读取 |
| 命令执行 | `IProcessRunner`，使用结构化参数与有界输出解析，不通过 shell 拼接命令 |
| 配置与日志 | `IPluginSettingsStore`、`IAppPaths`、`IAppLog`，不逐文件刷屏或记录内容/凭据 |

接口事实以 [PluginContracts](../../TractorTool.Contracts/PluginContracts.cs)、[ProcessRequest](../../TractorTool.Contracts/Processes/IProcessRunner.cs)及[插件接入规范](../PLUGIN_DEVELOPMENT.md)为准。目录业务与历史引擎不能写入宿主/Core；插件需要修改宿主、Core、Contracts 或公共 UI 时，按根 AGENTS 约定先停止该项修改并交架构侧分析。

## 5. 可靠性与首版边界

| 情况 | 必须落实的行为 |
| --- | --- |
| 变化监听 | 文件系统事件只作为“需要核对”的信号；合并重复事件，启动、重连、缓冲溢出后重新核对。不能把事件列表当作完整目录事实，也不每个事件启动一次工具 |
| 持续写入 | 设定稳定窗口、最小保存间隔和重试/延后策略；变化仍在持续时显示待保存，不宣称每次编辑均已捕获。具体数值需测量后定案 |
| 源目录离线/消失 | 显示不可用，保留旧历史；不能把暂时读不到解释为“全部文件已删除”并生成空版本 |
| 部分失败 | 文件被占用、拒绝访问、读取中变动时报告缺项；不完整结果不可作为最新完整版本或恢复前保护成功的依据 |
| 同时操作 | 同一目录的保存、原地恢复和历史清理互斥；恢复期间暂停自动捕获，完成后重建观察基线。跨目录并发设合理上限 |
| 空间不足 | 预估首次保存/恢复临时空间，显示占用与失败；不以释放空间为由删除工作文件或未授权的重要历史 |
| 版本保留 | 重要版本及待处理恢复使用的版本不可自动清理；显式核对引擎默认保留策略与维护任务，规则可见、可解释。规则或重要标记损坏时停止自动删除。先确认要删除的版本，再由引擎回收数据，不能自行递归删除内容块 |
| 完整性 | 校验快照可读取及恢复内容；识别损坏、未知格式、工具错误与输出截断，不能凭进程退出或存在一个历史条目就报成功 |
| 路径边界 | 规范化路径并检查大小写、目录重叠、相对路径越界、链接/重解析点与恢复目标冲突；恢复和删除前重新确认目标，不能只在添加目录时检查 |

首版建议支持普通文件内容、文件名、目录结构（含空目录）与经过验证的必要属性。Windows ACL、ADS、硬链接、稀疏文件、符号链接、云端占位文件、网络盘及超长路径分别列出支持范围；不支持时明确提示或拒绝，不静默跳过后声称完整保护。

运行中的数据库、虚拟机及多文件工程不因“创建快照”这个名称就具有同一时刻的一致性。普通逐文件读取不能保证应用一致；首版提示停止相关写入后保存。VSS、应用协作快照、管理员服务和内核驱动不自动纳入范围。

暂不开发分支/合并、Git 远程互通、云同步、团队协作、通用二进制语义对比、全天候独立 Windows 服务或新的公共备份平台。同盘历史用于误改/误删恢复，不能宣传为防硬盘损坏的异地备份。

## 6. 实施顺序与交接要求

1. **先完成选型核对**：确认首版范围、自动保存建议、工具版本/许可、凭据传递、历史库与宿主迁移/升级回退的关系。框架缺口独立交接，不能先改公共接口再补说明。
2. **最小完整路径**：在临时数据下验证建立历史、保存混合文件、列出两个版本、提取单文件/整目录并核对原始字节。验证授权另行取得，不能把本次文档任务当作运行授权。
3. **恢复可靠性**：完成恢复前保护、范围预览、并发写入冲突、失败/取消/重启后的处理，再开放原地回退。
4. **普通用户交互**：完成时间线、变化列表、文本对比、自动调度、立即保存、重要版本、停止/重新开启和清理；是否默认开启自动保存按定案落实，不能只做手动演示就宣称满足自动保护。
5. **独立交付**：按公共规范独立构建插件、校验宿主未变化，记录真实安装与运行结果；后续 Review 重点检查数据损失路径、任务生命周期、重复实现和悬空代码。

实施不要求新增所有可能用到的模块。按实际职责组织少量插件代码，优先复用引擎和已有公共能力。后续 Agent 不得把本文的设计与验收清单直接勾为完成；实际结果回填开发台账，详细证据按仓库约定归档。

## 7. 验收方法

以下是待实施的验证要求，不是本次已执行结果。使用临时样本和隔离数据根，运行由用户另行授权；不得在真实用户目录注入故障。

| 范围 | 验收要求 |
| --- | --- |
| 零手工环境准备 | 未安装 Git/引擎的 Windows 环境，通过宿主依赖流程完成首次保护；拒绝/断网/校验失败均不产生虚假的成功状态 |
| 混合内容 | 文本、多编码、图片、二进制、大文件和空目录经多次增删改后可恢复；逐文件哈希及目录清单一致，不仅验证文件存在 |
| 历史对比 | 两版本的新增/修改/删除与实际操作一致，覆盖同大小/同时间戳但内容变化的情况；文本增删行正确，未知二进制明确降级，原始内容和换行未被预览改写 |
| 自动调度 | 连续保存、批量复制、删除重建、监听事件溢出/丢失、重启后补查不遗漏最终状态；无变化不重复保存，不出现任务洪峰 |
| 恢复范围 | 单文件与整目录、原地与另存均验证；处理新增文件符合预览，排除项和无关文件不被删除，历史里的后续版本仍可用 |
| 恢复失败 | 保护失败、覆盖前新修改、文件占用、近满盘、取消/强制中断后保留恢复材料；重启可明确处理未完成状态，不能误报成功 |
| 目录身份 | 重命名、移动、盘符变化、暂时离线、同路径换目录不清空旧历史，重新关联有明确确认；重叠/链接路径不越界 |
| 关闭与清理 | 停止保护、禁用/卸载插件均保留当前文件与历史；删除历史不触及工作目录，重要版本和活动操作的引用不会被回收 |
| 凭据与迁移 | 日志/参数无明文秘密；凭据导出后在独立环境恢复成功；宿主迁移、插件更新/回退、旧配置与新历史兼容行为明确 |
| 生命周期 | 保存/恢复期间切页、隐藏到托盘继续工作；显式退出按宿主策略取消并记录结果，无遗留进程、锁或悬空监听 |
| 性能与可理解性 | 大文件、多小文件、已压缩/加密样本分别记录耗时、CPU/内存和新增磁盘占用；普通用户可看懂状态并完成一次找回，不能用模拟进度替代真实操作 |
