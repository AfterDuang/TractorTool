## 2. 当前开发与验收入口

开发 IDE 为 **VS Code**，使用根 `TractorTool.slnx` 与既有 `Avalonia: TractorTool` 启动项。工程旧提示可通过 `Developer: Reload Window` 重新载入；C# 属性变化后先构建，再 **Restart Previewer**。不要另建解决方案或给宿主添加具体插件引用。

以下是可用操作，**不是本次执行记录**；运行部分由用户决定。从仓库根目录执行：

```powershell
# 日常开发，不要求预先发布 SDK
dotnet restore .\TractorTool.slnx
dotnet build .\TractorTool.slnx -c Debug -m:1 -nr:false
# 隔离启动；默认 F5 没有隔离参数
dotnet run --project .\TractorTool\TractorTool.csproj -- --profile-root H:\ProjH\TractorTool\artifacts\manual-profile
# 仅发布到新空目录；正式插件另行构建/打包
.\scripts\Publish-Host.ps1 -Output H:\ProjH\TractorTool\artifacts\manual-publish
```

`--profile-root` 必须是绝对路径，将启动指针和默认业务数据一起隔离；不带参数时使用真实 `%LOCALAPPDATA%\TractorTool`。它是开发隔离参数，不是数据迁移功能。插件仍位于该宿主实际软件目录的 Plugins。

独立构建/打包教程维护在 [插件规范第 6 节](PLUGIN_DEVELOPMENT.md#6-开发构建与安装验证)。日常编译不会替换已安装 DLL；已装 1.1.0 需安装 1.1.1 ZIP 后**显式退出并重启**，关闭窗口仅隐藏。已装 1.1.1 不应重复安装同版本。

M2 UI 验收副本（E22，不含本轮进程服务；如果产物已清理，按发布与打包脚本重新生成隔离副本）：

```powershell
& .\artifacts\m2-motion\host\TractorTool.exe --profile-root H:\ProjH\TractorTool\artifacts\motion-manual-profile
# ZIP：artifacts/m2-card-layout/clipboard/TractorTool.ClipboardHistory-1.1.1.zip
```

M2 待用户验收：

1. 单 ZIP 拖入/选择安装、确认取消、非法来源拒绝；宽窄窗口、高 DPI、滚动后的遮罩边界及插件卡片布局。
2. 点击和拖动启停开关的滑动/按压、反向取消、失败复位、显式退出重启后的实际状态；安装/更新/卸载/回退与数据保留，隔离环境下的 ACL/占用及中断恢复。
3. 剪贴板空历史/关闭/拒绝/失效，左右分栏与选择、空选择控制台、长文本/图片预览、复制原项后实际粘贴；不清空真实历史。
4. 在其他应用复制临时内容后返回，检查事件/激活刷新、原选择保留；快速选图/切页不出现迟到预览。无自建历史和定时轮询。
5. 关闭/重新开启“界面动画”后检查现有和新打开页面的开关、按钮、展开及切页；深浅主题、缩放、导航、持久化及托盘回归。需要完整 M1 清单时按需看 [历史回归步骤](PROJECT_HISTORY.md#m1-manual-checklist)。

可用检查入口：核心断言程序为 `dotnet run --project .\tests\TractorTool.Checks -c Release`；完整机制验证为 [Verify-M1.ps1](../scripts/Verify-M1.ps1)，会构建、运行核心、发布、独立编译测试插件、运行 Headless 并核对哈希。它们不是 `dotnet test` 项目，未经新的测试指示不自动执行。模型替身不证明 Windows API，VM 安装检查不证明原生 Drop 路由。

该核心入口现包含 M3 进程用例：4 项故障/竞争替身检查，Windows 下另有 13 项真实子进程夹具检查（参数、双管道、超时/取消、父先退出及调用间隔离）。只使用本检查程序和随机临时目录，不调用 FFmpeg 或操作用户文件；本轮只编译未运行。没有适配器的平台明确跳过 Windows 部分，不可算通过。旧 API 1.0 DLL 与新宿主的实际加载也需重新验证。

宿主实现软件目录 Plugins 的安装、更新、禁用、卸载待重启事务及失败恢复，覆盖重复 ID、损坏清单、缺 DLL、不兼容、不可写和文件占用；不重定向到数据目录。

当前代码与打包已落实上述范围，15 项核心管理、20 项剪贴板模型、8 项管理 UI 及 2 项共享动效用例仅编译。剪贴板 1.1.1 修复空选择绑定；宿主更新管理卡片及动画策略。变更生效、快照回退、ACL/占用、真实系统读取等仍待运行验收，暂不宣称 M2 全部通过。

### M3：公共依赖服务与媒体验证

已有进程契约、Core 调度/清理、Windows Job 适配及插件生命周期接入，尚未运行验证。没有下载 FFmpeg、没有媒体导出页面或模拟输出。包服务可继续开发，进程夹具实测仍是阶段出口所需证据；包未接入前清单非空 dependencies 继续拒绝。

按 [架构：包和进程服务](ARCHITECTURE.md#packages) 实现 Contracts/Packages、Core/Packages 与宿主管理页，FFmpeg/ffprobe 文件放 DataRoot/Packages。验证下载/校验/解压、固定版本来源和许可、并存/占用、重试。

按 [视频插件设计](Plugins/VideoExport.md) 实现探测、基本参数校验、单次导出、进度和取消，尽早取得单视频真实转码、严格首帧替换及至少一条实际 GPU 路径的证据。定稿初始多格式矩阵；缺硬件仍记未验证。

### M4：完整视频交互与任务

完成 [视频插件](Plugins/VideoExport.md) 的单视频/单封面输入、多预设卡片和持久化、码率大小预估、不可变快照、全队列串行、进度与取消、首帧替换、多格式及 GPU 交互。

阶段出口是同一视频按多预设产生独立、正确、可播放的真实文件，切页/隐藏不中断，重启保留预设和设置。详细模型、算法、失败策略和媒体判定只维护在插件文档。

### M5：可靠性与发布

实现数据根迁移、固定启动指针与失败恢复；下载包和插件数据随数据根迁移，软件目录的插件代码不动，旧数据默认保留。完善退出、关机、有界进程清理、中断摘要、临时输出、日志保留，覆盖空间不足、冲突和更新失败。

本地与 GitHub Actions 复用发布流程，提供 Windows 安装包/压缩包、SHA256 和许可，验证无开发 SDK 的机器启动和加载。最低系统、架构、安装器、签名和设备支持由真实证据落实；不照搬参考软件结论。

## 5. 验证与发布要求

- 静态、构建、自动化、集成/Headless、真实 UI/系统/硬件分别报告；未执行、失败和阻塞不能记为通过。按风险选检查，不为简单样式写镜像实现测试。
- 集成采用真实独立插件和隔离目录；媒体使用短合成样本与真实 FFmpeg，核对首帧/后续画面、时长和音画同步，不以返回码、文件存在或模拟进度替代。

- M5 再落实 CI、压缩包/安装器、SHA256、签名、最低系统、无开发 SDK 机器验证。不得发布用户数据、缓存、令牌或本机工具副本；记录第三方及 FFmpeg 来源、版本和许可。
- M3–M4 必须取得实际 FFmpeg 包/格式矩阵、首帧/VFR、GPU 编码证据；M2 先取得 Windows 历史内容类型与管理闭环证据。缺设备或权限时保留限制。
