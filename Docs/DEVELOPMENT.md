## 2. 当前开发与验收入口

开发 IDE 为 **VS Code**，使用根 `TractorTool.slnx` 与既有 `Avalonia: TractorTool` 启动项。工程旧提示可通过 `Developer: Reload Window` 重新载入；C# 属性变化后先构建，再 **Restart Previewer**。不要另建解决方案或给宿主添加具体插件引用。

以下是可用操作，**不是本次执行记录**；运行部分由用户决定。从仓库根目录执行：

```powershell
# 日常开发，不要求预先发布 SDK
dotnet restore .\TractorTool.slnx
dotnet build .\TractorTool.slnx -c Debug -m:1 -nr:false
# 隔离启动；默认 F5 没有隔离参数
dotnet run --project .\TractorTool\TractorTool.csproj -- --profile-root H:\ProjH\TractorTool\artifacts\manual-profile
# 仅发布到新空目录；正式插件另行构建/打包
.\scripts\Publish-Host.ps1 -Output H:\ProjH\TractorTool\artifacts\manual-publish
```

`--profile-root` 必须是绝对路径，将启动指针和默认业务数据一起隔离；不带参数时使用真实 `%LOCALAPPDATA%\TractorTool`。它是开发隔离参数，不是数据迁移功能。插件仍位于该宿主实际软件目录的 Plugins。

独立构建/打包教程维护在 [插件规范第 6 节](PLUGIN_DEVELOPMENT.md#6-开发构建与安装验证)。日常编译不会替换已安装 DLL；已装 1.1.0 需安装 1.1.1 ZIP 后**显式退出并重启**，关闭窗口仅隐藏。已装 1.1.1 不应重复安装同版本。

本轮日志与管理冲突验收副本目标（E35；生成结果以第 1 节证据为准）：

- 宿主：`artifacts/log-follow/host-final/TractorTool.exe`，使用新的 `--profile-root` 隔离数据；也可通过当前源码 F5 使用新宿主。
- 插件本轮未改，沿用 `artifacts/preset-task-review/video/TractorTool.VideoExport-0.5.2.zip`；已安装 0.5.2 不要重复安装。尚未安装时拖入、确认后**显式退出并重启**。它要求 API 1.7 / UI 1.3，源码编译不会自动更新已装 DLL。
- 安排安装后再次选择同一插件或其他版本：提示待重启，记录无异常堆栈的 ERROR；原请求/暂存保留，本次拒绝的暂存清理。同版本、旧版本冲突给出实际原因；真实文件/包故障不能被吞掉。
- 新输出应为 `视频名_预设名.mp4`，中文/空格保留；非法字符清洗、超长主干截短，同名文件/目录冲突依次 `_2`、`_3`，不覆盖。现有旧输出不重命名。公共任务按钮显示所属插件名，打开对应插件；卸载后旧摘要入口转到插件管理。多插件同批次 ID 的取消互不影响。
- 右上角切换“多格式导出 / 视频信息”；信息页左侧拖一个视频自动识别，右侧文本可全选/复制，无播放或首帧预览。核对多音轨/字幕、章节、嵌套元数据、损坏/非视频输入及宽窄窗口滚动。
- 左侧输入一个视频及可选封面，编辑格式/码率模式/视频和音频码率后添加预设；尺寸与首帧替换在“画面选项”，输出目录统一在右下方。右侧编辑/复制/删除/勾选，重启后参数保留而输入路径不保存。改变名称不能改变参数，验证单项取消、整批取消与失败后余项。
- 使用临时合成视频，关闭 GPU 加速，分别按 VBR 一次/VBR 两次/CBR 导出 MP4/MKV/MOV/WebM/TS，检查实际画面/尺寸/音轨/时长和进度；再开启首帧替换，验证透明/不同比例封面、CFR/VFR、旋转和音画同步。再在插件设置开启 GPU 加速，检查实际使用、硬件不可用/完整编码失败/VBR 两次/WebM 的 CPU 回退说明；只有实际硬件输出才记录 GPU 通过。详细媒体判定见[插件验收方法](Plugins/VideoExport.md#6-验收方法)。
- 导出期间切页/隐藏应继续，取消应停止本次进程并清理自己的临时文件；已有同名文件和源文件保留。HDR/高位深/显式广色域/隔行等未支持输入需明确拒绝；另测 BT.709、full-range 和彩色封面，未标记色彩不能视为已证明正确。此版按勾选卡片串行导出，可取消当前/等待项或整批，某项失败继续余项；运行期间锁定输入和预设编辑。
- “日志 → 任务进度”在其他工具/设置页可达，核对整批状态、进度、单项和整批取消、结果路径、返回工具。显式退出有活跃任务时分别选择继续处理/停止退出；关闭到托盘应继续。仅用隔离 profile 验证异常结束后重启：非终态显示中断、不自动执行、不删除残留输出；坏任务文件保留并阻止新任务，修复后可重试保存。正常提交后遇到迟到取消仍须显示成功和结果路径。
- 日志页检查绿/黄/红、筛选/搜索/复制/折叠详情和任务实时进度；正文左右留白应与标题对齐，窄窗口工具栏换行。普通导航不新增记录。“已读”立即清除当时所有错误红点（含暂停/筛选隐藏项），保留日志，之后新错误再次提醒。记录从上到下旧到新，底部跟随；上翻不拉回、回底恢复；另测拖动滚动条、暂停恢复、300 条淘汰、改变窗口和详情高度。正常取消应为 INFO，真正故障有 ERROR；旧取消调试输出触发仍需记录。
- 依赖申请/媒体读取/参数预检仍显示于插件页，准备时可以取消，预检失败或选择“先不安装”不建公共任务；不能将下载或信息读取误判为公共任务页漏项。

### M2：插件管理与剪贴板

宿主实现软件目录 Plugins 的安装、更新、禁用、卸载待重启事务及失败恢复，覆盖重复 ID、损坏清单、缺 DLL、不兼容、不可写和文件占用；不重定向到数据目录。

独立交付 [剪贴板插件](Plugins/ClipboardHistory.md)，真实 Windows 历史读取/刷新及状态显示符合该文档。阶段出口是管理闭环和 A08 的真实系统证据，不接受自建历史库替代。

当前代码与打包已落实上述范围，15 项核心管理、20 项剪贴板模型、8 项管理 UI 及 2 项共享动效用例仅编译。剪贴板 1.1.1 修复空选择绑定；宿主更新管理卡片及动画策略。变更生效、快照回退、ACL/占用、真实系统读取等仍待运行验收，暂不宣称 M2 全部通过。

### M3：公共依赖服务与媒体验证

已有进程、包契约、Core 事务/租约、Windows Job 和设置入口。固定 FFmpeg ZIP 曾做哈希/结构/许可静态核对，未运行程序或经服务安装到数据根。视频插件已接单次导出、首帧滤镜和 GPU 试编码路径；没有执行 ffprobe/FFmpeg，没有真实媒体输出证据，不能判定 M3 出口通过。

包服务按 [架构](ARCHITECTURE.md#packages) 分层，FFmpeg/ffprobe 放 DataRoot/Packages。用例覆盖下载事务及申请确认、共享等待、引用保护、源移除、当前源修复、旧 receipt 升级失败和待重启/回退引用，仅编译。仍需实际网络、工具版本探测、磁盘/权限/占用和崩溃恢复证据。

按 [视频插件设计](Plugins/VideoExport.md) 实现探测、基本参数校验、单次导出、进度和取消，尽早取得单视频真实转码、严格首帧替换及至少一条实际 GPU 路径的证据。定稿初始多格式矩阵；缺硬件仍记未验证。

### M4：完整视频交互与任务

完成 [视频插件](Plugins/VideoExport.md) 的单视频/单封面输入、多预设卡片和持久化、码率大小预估、不可变快照、全队列串行、进度与取消、首帧替换、多格式及 GPU 交互。

公共有限任务已接入：预检后一次登记整批，逐项执行并报告通用进度，日志内任务进度入口可查看/取消/返回工具；显式退出确认及重启中断摘要已有实现。参数与串行策略归插件，摘要不保存业务参数、不自动续转码或清理崩溃输出。

阶段出口是同一视频按多预设产生独立、正确、可播放的真实文件，切页/隐藏不中断，重启保留预设和设置；任务取消、退出和中断摘要需要用户运行验证。实现补齐不代表阶段出口通过，详细模型、算法、失败策略和媒体判定只维护在插件文档。

### M5：可靠性与发布

实现数据根迁移、固定启动指针与失败恢复；下载包、任务摘要和插件数据随数据根迁移，软件目录的插件代码不动，旧数据默认保留。对已有退出、关机、有界进程清理与中断摘要补可靠性验证，完善临时输出、日志保留，覆盖空间不足、冲突和更新失败。

本地与 GitHub Actions 复用发布流程，提供 Windows 安装包/压缩包、SHA256 和许可，验证无开发 SDK 的机器启动和加载。最低系统、架构、安装器、签名和设备支持由真实证据落实；不照搬参考软件结论。

### 后续计划（未排期）

用户已确认 Python / pip 依赖支持作为后续计划：由宿主统一准备解释器和隔离环境，通过 PyPI / 兼容源安装，保留首次确认、依赖复用、引用保护和主动清理语义。具体边界见 [架构方案](ARCHITECTURE.md#python-dependencies)。该规划仅涉及文档，未实现 Python 安装；本地 AI 的模型选择、推理及工作流仍属插件业务，不提前扩建框架。规划记录见 [E28](PROJECT_HISTORY.md#evidence-python-plan)。

- 静态、构建、自动化、集成/Headless、真实 UI/系统/硬件分别报告；未执行、失败和阻塞不能记为通过。按风险选检查，不为简单样式写镜像实现测试。
